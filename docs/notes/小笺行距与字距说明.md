# 第二档：行距与字距（顺手接管了横排换行）

版本 0.9.5。

第二档原本有四件：行距、字距、文字描边/阴影、字体预设。这一轮做的是**间距**——行距和字距共用一套排版管线，一起做最省，也是第二档里视觉收益最大的一块。

---

## 一、为什么行距/字距要动排版核心

横排文字以前是这么画的：

```csharp
TextRenderer.DrawText(graphics, Text, Font, bounds, ForeColor,
    TextFormatFlags.WordBreak | HorizontalFlags() | VerticalFlags() |
    TextFormatFlags.EndEllipsis | TextFormatFlags.NoPadding | TextFormatFlags.NoPrefix);
```

**GDI 的 `WordBreak` 既不能调行距，也不能调字距。** 这两个东西在 `TextFormatFlags` 里根本没有对应项，`Graphics.DrawString` 也没有。

所以想加行距/字距，就必须自己接管换行：先算出每一行断在哪儿，再一行一行画。

这件事的危险之处不在于「自己换行」难，而在于**它会制造第二套规则**。这个项目有一条硬约束：

> 字体自适应、隐形点击框、拖动下限，全都调 `QuoteView.MeasureBlock()`。量出来和画出来的必须是同一个东西。

如果绘制自己换行、测量还交给 GDI，两边迟早分家——而那正是竖排当初踩过的坑（一个用 `MeasureString`、一个用 `MeasureText`，竖排后各算各的，必然错位）。

**所以这一轮的核心不是「加两个设置」，而是「换行只有一处」。**

## 二、结构

### 新增 `TextLines`（纯逻辑，可单测）

```csharp
internal static class TextLines
{
    public static List<string> Split(string text, int available, Func<char, int> advance);
    public static string Shorten(string line, int available, Func<char, int> advance);
}
```

`Split` 的做法：每行尽量填满；**遇到空格优先在空格处断**（英文单词不被劈开），中文没有空格、本来就该在任意两字之间断；文本里的 `\n` 永远断行，连续两个换行留一个空行。

`advance` 是「一个字符多宽」的回调——**字母间距就是通过它进来的**，换行器本身不知道「间距」这个概念。

### 一个字符宽度表

`TextLines` 要的是每个字符的宽度，而**自适应字号会在大约五十个不同宽度上量同一段文字**。每次重新测量每个字符，拖动卡片就会卡。

所以 `QuoteView` 里加了一张按字符缓存、跟着字体失效的宽度表：

```csharp
private Font _metricsFont;
private int _metricsLineHeight;
private readonly Dictionary<char, int> _advances = new Dictionary<char, int>();
```

字体一换就整表清空重测。这样换行器是纯算术，`MinimumFor` 的五十次探针不再有 GDI 开销。

### 行高用 GDI 的数，不用 `Font.Height`

```csharp
_metricsLineHeight = Math.Max(1, TextRenderer.MeasureText("字", font, ...).Height);
```

用 `Font.Height` 更省事，但那是 GDI+ 的算法，和 GDI 的 `tmHeight` 不是一回事。**卡片的拖动下限是建在 GDI 那个数上的**，换掉它会让每一张已经存在的卡片都动一下。所以这里取 GDI 量一个汉字得到的高度。

### 测量与绘制

```csharp
private Size MeasureHorizontal(Font font, int viewWidth)
{
    List<string> lines = BuildLines(font, viewWidth);      // ← 唯一的换行
    ...
    int height = lines.Count * natural + (lines.Count - 1) * LineGap(font);
}

private void PaintHorizontal(Graphics graphics)
{
    List<string> lines = BuildLines(Font, Width);          // ← 同一个换行
    ...
    for (int index = 0; index < visible; index++) { ... }
}
```

行距加在**行与行之间**（`(n-1)` 个间隙，最后一行下面不加），所以 `100%` 时块高和以前完全一样。

### 竖排：间距加在「格」上

竖排本来就是逐字画的，`MeasureCell` 给出的 `cellWidth`/`cellHeight` 同时决定「一列能放几个字」和「每个字画在哪」。所以间距直接加在格上：

```csharp
cellHeight += round(natural * letterPercent / 100);     // 字距 = 列内字与字的间距
cellWidth  += round(cellWidth * (linePercent - 100) / 100);   // 行距 = 列与列之间的间距
```

量测和绘制读的是同一对数字，不可能分家。

### 对齐变成逐行摆

以前是把整块交给 `TextFormatFlags.HorizontalCenter` 之类。现在每行自己算位置：

```csharp
int originX = TextMargin + AlignOffset(available - width, _horizontalAlignment);
```

**顺带的好处**：右对齐时每行都贴着右边（以前整块居中/右对齐，但行内还是左起）。**顺带的代价**：`HorizontalFlags` / `VerticalFlags` 这两个辅助函数没用了，删掉。

## 三、为什么用百分比

`LineSpacingPercent`（70–250，默认 100）和 `LetterSpacingPercent`（0–100，默认 0）。

字号跟着卡片变，所以固定的像素间距在大卡片上看不见、在小卡片上会把字挤没。百分比乘的是「当前字体的行高」，字号一变间距自动跟着变。

## 四、升级会看到什么

- **默认值就是旧行为**：行距 100% 时块高与以前完全一致，字距 0% 时宽度也一致
- **中文折行结果不变**：汉字是等宽的，逐字宽度相加与 GDI 一致
- **西文会略微提前断行**：逐字相加没有字偶距（kerning），算出来的宽度比 GDI 略大。这是接管的代价，写在 CHANGELOG 里
- **右对齐/两端的变化**：现在逐行对齐，右对齐时每行贴右边

## 五、验证

### .NET 8 纯逻辑工程（`/tmp/mqc-harness/`）

`TextLines` 是纯算术，所以能在 macOS 上**跑真实代码**。新增 15 项，当前 **135 项全过**：

- 10 个字、每行 5 个 → 2 行且对半
- 装得下就只有一行；空文本没有行
- **单个字符比整行还宽也照样前进，不会卡死**
- 空格是首选断点（`aaaa bbbb` 在 45px 处断成 `aaaa` / `bbbb`），断点处的空格被丢掉
- `\n` 照样断行；两个换行之间留一个空行；CRLF 当成一个换行
- 字宽翻倍时行数跟着变（间距通过 `advance` 进来）
- 截断补省略号，并且截断之后**真的不超过行宽**

### 源码级断言

`verify_font_library.py` 新增 **F15 组**：`Forms.cs` 里**不许再出现** `TextFormatFlags.WordBreak` / `EndEllipsis`；`MeasureHorizontal` 和 `PaintHorizontal` 都必须走 `BuildLines`；`MeasureCell` 必须把两个百分比算进格子；字段/夹取/保存/读取八处；两个子菜单各四档的标题；`MarkCurrent` 标出当前档；两个 setter 必须重新适应 + 长卡片。

**10 条反向注入全部报出**，当前 **53/53**。

`verify_portable_align.py` 的 **P3 组**改成认新的对齐实现（`AlignOffset` 两条轴各一次、不许写死居中、必须走 `BuildLines`），并**补上了锚点唯一性检查**——加完代码后立刻抓出三条锚点不再唯一的老注入。

### 自检（`Windows`）

新增断言 **179–186**：窄卡片（80×400）上把行距从 100% 拉到 250%，块高必须变大、文字仍然完整、拉回去必须还原；字距从 0% 拉到 100% 块宽必须变大；两项都夹在范围内。

自检断言总数 176 条，最大编号 186，无重复。

### 顺手修掉的验证漏洞

加代码让三条老注入的锚点不再唯一（`verify_portable_align.py` 里原本没有唯一性检查）。现在四个源码断言脚本**都有**这条检查了。
