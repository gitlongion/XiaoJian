# 字号调整失灵 + 每张卡片独立内容库

本文说明这一版改了什么、为什么这么改，以及在 macOS 上能验证到什么程度。

---

## 一、「字体大小调整失灵」

### 结论：不是没接上，是被「自动适应」原样吃回去了

「文字设置 → 大一点 / 小一点 / 设为最小 / 恢复默认字号」四项在源码里一直是接上的，
问题出在**字号是怎么算出来的**：

```csharp
// 旧代码
float start = Math.Min(29.0f, Math.Max(20.0f, Width / 17.0f)) + _card.FontAdjustment;
float chosen = Math.Max(7.0f, start);
if (_card.AutoFitText)
{
    for (float size = start; size >= 7.0f; size -= 1.0f)
        if (_quoteView.FitsBlock(candidate)) { chosen = size; break; }   // 第一个装得下的
}
```

`FontAdjustment` 只是**搜索起点上的一个偏移**。真正决定字号的是后面那轮「从起点往下找、
第一个装得下的字号」——**而它只跟卡片大小有关，跟这个偏移无关**。于是：

- 卡片比较空（文字只占几行）→ 起点本身装得下 → 字号 = 起点 + 偏移 → 点了有用；
- 卡片正好装住文字 → 「装得下的最大字号」已经被卡片钉死了 → **偏移多大都一样**。

第二种情况恰恰是上一版「卡片可以拖到最小、最小就是文字区域」刚刚大量制造出来的卡片：
把卡片拖到下限，字号就被钉在 7 磅，四项**全部**失效。

### 仿真给出的证据

`verify_font_sim.py` 用与 `Forms.cs` 一一对应的算术（点 → 像素 → 折行 → 行高、
`FitsBlock`、`MinimumFor`）枚举「卡片尺寸 × 文字长度 × 偏移」：

```
== 1. 缺陷复现：旧实现下「大一点」会被自动适应吃回去 ==
  [OK ] 旧实现在 6/10 种场景下「大一点」完全无效
  [OK ] 其中 6/10 种场景下「大一点」和「小一点」同时无效（字号被钉死）
```

默认卡片（460×190）上，逐字加长文字，看「大一点」是否改变字号：

| 文字长度 | 4~30 字 | 31~60 字 |
|---|---|---|
| 「大一点」有效 | ✔ | ✘（30/57 个长度下无效） |

拖到下限的卡片上，`FontAdjustment` 取 −24 … +8 九档，字号**全部**是 7.0 磅。

### 修法

新增 `CardState.ManualFontSize`：**用户手选的绝对字号**。四项菜单不再改偏移，而是接管字号：

```csharp
private void SetManualFontSize(float size)
{
    _card.AutoFitText = false;                       // 字号从此由你定，卡片不许改回去
    _card.ManualFontSize = Math.Max(CardState.MinManualFontSize,
        Math.Min(CardState.MaxManualFontSize, size));
    _quoteFontSize = -1.0f;                          // 缓存失效，避免「算出来一样」的假象
    _app.Save();
    FitQuoteFont();
    GrowCardToText();                                // 字变大 → 卡片跟着长，文字不被裁
}
```

- `FitQuoteFont()` 里新增一条分支：`!AutoFitText && ManualFontSize > 0` 时**直接用这个值**，
  不再走「往下找」的搜索。
- `GrowCardToText()` 只增不减，长到装得下为止；因为手动字号是绝对值、不随卡片变，
  所以一趟就收敛，不会出现「卡片变大 → 字号变大 → 卡片又变大」的自激。
- 「恢复默认字号」= 偏移归零 + 清手动字号 + **重新勾上自动适应**（默认就是自动适应）。
- 「文字自动适应卡片」勾回来时会顺手清掉手动字号，交还控制权。

副作用只有一个，而且是可见的：点完「大一点」，菜单里的「文字自动适应卡片」会被取消勾选。
这是诚实的——字号和「跟着卡片自动变」本来就互斥，用户想交还随时可以勾回来。

`CardState.MinManualFontSize = 7f` 与 `QuoteView.SmallestFontSize` 现在是同一个来源
（`public const float SmallestFontSize = CardState.MinManualFontSize;`），不会再各写一个 7。

## 二、每张卡片独立内容库

### 改法

`CardState` 新增**稳定槽位** `Slot`（发出去就不回收），内容库按槽位一卡一份：

```
%LOCALAPPDATA%\MyQuoteCard\
    state.ini
    content-1.txt        ← 第 1 张卡片的内容库
    content-2.txt        ← 第 2 张卡片的内容库
    background-1.png     ← 第 1 张卡片的背景图
```

- 文件名用**槽位**而不是「第几张」：插入或删除卡片不会让某张卡片突然读到别人的内容。
- `QuoteRepository.ForCard(state, dataDirectory, card)` 是唯一的建库入口；
  `CardManager` 不再持有单一仓库，改为在 `AddForm` 里按卡建。
- 编辑器标题会写出是哪一张：「编辑内容库 · 卡片 2」，多张卡片时不会看不出在改哪一份。

### 旧数据迁移

旧版所有人的内容都在一个 `quotes.txt` 里。启动时 `QuoteRepository.MigrateSharedLibrary()`
把它**改名**给第一张卡片的文件（`content-1.txt`）：

- 改名而不是复制：目录里始终「一张卡片一个文件」，不留一个应用已经不再读的旧文件；
- 改名失败（文件被占用、目录只读）退回复制——为了目录好看而丢内容是不划算的；
- 已经迁过就什么都不做，重复启动不会破坏内容。

### 顺带修掉的多卡缺陷：背景图共用

`ChooseBackgroundImage()` 原来写死 `background.<扩展名>`，**所有卡片共用一张背景图**，
最后选图的那张卡片会把别的卡片的背景一起换掉。现在改为 `background-<槽位>.<扩展名>`；
并且删旧图之前会先扫一遍 `_app.Cards`，确认没有别的卡片还指着同一个文件才删
（旧文件是共用的，卡片可能正指着它）。

### 新增的自检（`MyQuoteCard.exe --self-test`，在 Windows 上跑）

- 70~86：槽位分配与持久化、两张卡片的内容库文件不同名、共享库迁移（改名、不留旧文件、
  再迁一次不破坏）、两张卡片内容互不干扰、手动字号往返与夹取；
- 87~93：在**已经拖到下限**的卡片上点「大一点」必须真的变大、卡片跟着长到装得下、
  「小一点」同样生效、「设为最小」落在 7 磅。

### 还没验证的

`SelfTests` 里 87~93 这组断言依赖真实 GDI+ 的文字测量（`TextRenderer.MeasureText`），
只能在 Windows 上跑。macOS 这一侧用 `verify_font_sim.py` 的模型覆盖了同一组性质：
在全部 10 种「卡片 × 文字」组合、4 张下限卡片上，四项都真的改变字号，且变大之后文字仍装得下。

真机还需要确认的：拖拽缩放的收放手感、UAC 提权、系统任务注册与执行、
以及真实字体（微软雅黑 / 宋体）下的行高与折行位置。
