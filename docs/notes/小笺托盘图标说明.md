# 托盘图标为什么没跟着换

版本 0.9.3。

用户反馈：

> 右键图标更新了，但是托盘图标和程序图标没有更新

这两件事其实是**两回事**，一个是程序的错，一个不是。

---

## 一、托盘图标：代码里另画了一张

程序的图标一共有三个出处：

| 位置 | 从哪儿来 |
|---|---|
| 窗口图标（Alt+Tab、右键菜单） | `Form.Icon` 默认取 exe 自己的图标资源 |
| exe 文件图标（资源管理器） | exe 里嵌的 `RT_GROUP_ICON` |
| **托盘图标（通知区域）** | **`CreateTrayIcon()` 里手绘的** |

前两个在 0.8.0 换 `card.ico` 时一起变了。第三个根本没走图标文件：

```csharp
private static Icon CreateTrayIcon()
{
    using (Bitmap bitmap = new Bitmap(32, 32))
    using (Graphics graphics = Graphics.FromImage(bitmap))
    {
        using (Brush background = new SolidBrush(Color.FromArgb(8, 8, 8)))
            graphics.FillEllipse(background, 1, 1, 30, 30);          // 深色圆底
        using (Font font = new Font("Georgia", 20, FontStyle.Bold, GraphicsUnit.Pixel))
        using (Brush foreground = new SolidBrush(Color.White))
            graphics.DrawString("“", font, foreground, new PointF(8, 6));  // 白色引号
        ...
    }
}
```

**这就是 `card.ico` 换掉之前那张图**——深色圆盘加一个白色引号。窗口图标从 exe 里取，所以跟着换了；托盘走的是这段代码，一直留在旧样子上。

### 修法

托盘图标改成**从 exe 的图标资源里取**，三级兜底：

```csharp
internal static Icon CreateTrayIcon()
{
    // 1. ExtractIconEx 取「小号」那一档 —— 通知区域就是 16×16，
    //    而 card.ico 里 16×16 是单独画的（描边加粗），缩下去才不糊。
    // 2. 取不到就 Icon.ExtractAssociatedIcon，让系统按自己的方式读这个文件。
    // 3. 都没有（exe 里根本没有图标资源）才用手绘那张。
}
```

`ExtractIconEx` 是新增的一条 P/Invoke（`shell32.dll`）。手绘的那段保留成 `DrawnTrayIcon()`，**只当最后兜底**。

### 为什么用 `ExtractIconEx` 而不是 `Icon.ExtractAssociatedIcon`

`Icon.ExtractAssociatedIcon` 拿到的是**大号**（32×32），托盘是 16×16，得靠系统缩——而 `card.ico` 里 16×16 那一档是**单独画的**（描边比 32 档粗），专门为这个尺寸准备。直接取小号那一档才是对的那张图。

## 二、程序文件图标：不是程序的错

`verify_exe.py` 把 exe 里的 `RT_GROUP_ICON` 和每个 `RT_ICON` 与 `card.ico` **逐字节比过**：

```
[OK ] RT_GROUP_ICON 的档数与 card.ico 一致（7 档）
[OK ] RT_GROUP_ICON 的档位序列与 card.ico 一致  -> [16, 24, 32, 48, 64, 128, 256]
[OK ] 每个 RT_ICON 的字节都与 card.ico 对应档完全相同
```

**exe 里嵌的确实是新图标。** 资源管理器里还显示旧的，是 Windows 的**图标缓存**（`IconCache.db`）没刷新——这是外壳的行为，不是程序能控制的。刷新办法：

- 重启电脑（最省事，一定有效）
- 或者：任务管理器里重启「Windows 资源管理器」
- 或者：把 exe 挪到另一个目录（路径变了就是新缓存项）

0.8.0 换图标时这件事也存在，只是当时用户先注意到的是别的。

## 三、验证

### 源码级断言（`verify_icon.py`，新增 I10 组）

查 `CreateTrayIcon` 的**方法体**（不是整个文件——`NativeMethods` 里也有 `ExtractIconEx` 的声明）：

- 必须调用 `ExtractIconEx`（托盘真的从 exe 取图）
- 必须有 `ExtractAssociatedIcon` 兜底
- 必须指向 `Application.ExecutablePath`（换机器、改名都对得上）
- 手绘兜底必须是方法体**最后一步**（否则它会盖掉 exe 里的图）
- 手绘图标的代码只许有一处（`FillEllipse` / `GetHicon` 各出现 1 次）——多一处就是「又有一处忘了换」

**4 条源码级反向注入全部报出**（锚点唯一性也检查了）；对 v0.9.2 的源码跑，I10 报出 4 条；对本版 0 条。

原有的 18 条图标字节注入仍然全过。

### 自检（`XiaoJian.exe --self-test`，Windows）

`CreateTrayIcon` 改成 `internal`，自检可以直接调它——`ExtractIconEx` 是 P/Invoke，**这是它唯一的实测**。

新增断言 **163–165**：

- **163/164**：托盘图标取得到、尺寸非零
- **165**：托盘图标的**平均亮度 ≥ 90**

第 165 条是判断「取到的是不是那张卡」的办法。`card.ico` 七档的平均亮度是 **132–156**（白纸），手绘那张是**约 23**（近黑圆盘占了大半面积，透明部分按 0 算）。90 离两边都远。

自检断言总数 155 条（不含成功码 0），最大编号 165，无重复。

### 完整验证

`sh verify_all.sh` 11 步全绿；`.NET 8` 纯逻辑 116 项；PE 校验含图标逐字节对照全过。

## 四、仍然验不了的

- `ExtractIconEx` 在真实 Windows 上返回的到底是哪一档（自检只能验「取到了、而且亮」）
- 通知区域在 125% / 150% 缩放下要 20×20 / 24×24 时，系统挑的是哪一档
- 资源管理器图标缓存刷新之后，用户实际看到的是哪一档
