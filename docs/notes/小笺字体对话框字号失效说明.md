# 字体对话框里的字号为什么失效

版本 0.9.2。

用户抱怨：

> 点大一点有反应，字体大小设置对话框里超过一定数字大小就失效

## 一、根因：字号被整个丢掉了

「文字设置 → 选择字体」打开的是系统字体对话框（`FontDialog`），它里面有字体名、字形，也有一个**字号**。改动前的处理是：

```csharp
_card.FontName = dialog.Font.FontFamily.Name;      // 收下字体名
_card.FontStyleValue = (int)dialog.Font.Style;     // 收下字形
_app.Save();
_quoteFontSize = -1.0f;
FitQuoteFont();                                    // ← 字号重新按卡片算一遍
```

**字号从头到尾没被读。** `FitQuoteFont()` 又按卡片自己算了一遍，于是对话框里选的字号等于没选。

那为什么用户说的是「**超过一定数字**才失效」，而不是「一直没用」？因为自动适应算出来的字号本来就落在**小的一侧**：选一个和它差不多的小值时看不出差别，选一个明显更大的值就露馅了。所以这个 bug 在视觉上正好长成「小数字有效、大数字失效」的样子。

## 二、修法

把「应用选中的字体」从对话框里拆出来，字号一起收下：

```csharp
internal void ApplyPickedFont(Font picked)
{
    _card.FontName = picked.FontFamily.Name;
    _card.FontStyleValue = (int)picked.Style;
    float before = CurrentFontSize();
    float size = picked.SizeInPoints;
    _app.Save();
    _quoteFontSize = -1.0f;
    if (Math.Abs(size - before) >= 0.05f)
        SetManualFontSize(size);     // 选了字号 → 手选字号 + 关掉自动适应
    else
        FitQuoteFont();              // 只换了字体 → 卡片自己重算
}
```

三个决定：

1. **选了字号就走 `SetManualFontSize`** —— 和「大一点 / 小一点 / 设为最小」完全一样：字号交给你，同时自动取消「文字自动适应卡片」。不取消的话，下一轮适应会把它原样吃回去（这正是原来那个 bug 的机制）。
2. **只换了字体名或字形（字号没动）时不碰自动适应的开关** —— 卡片保持自己算出的字号。换了字体之后度量不同，那正是自动适应要处理的事。只想换字体的人不该被莫名取消自动适应。
3. **对话框打开时显示卡片当前的字号**，不再固定从 12 磅起。否则「只换字体」会顺手把字号跳到 12。

拆出 `ApplyPickedFont` 还有个实际好处：这段逻辑**不用弹模态框就能跑到**，所以自检里能真的验它。

## 三、顺带修掉的一处验证盲区

改这条的时候发现一个更值得记的事：`verify_size.py` 里有 **8 条注入的锚点在源码中出现两次**，`str.replace(old, new, 1)` 只替换第一处，于是那些注入一直打在**另一处**上。

其中一条特别值得说：

| 注入 | 声称要验的 | 实际打到的 | 实际报出的组 |
|---|---|---|---|
| FitCardToText 不清空 MinimumSize | Z9（FitCardToText） | **构造函数**里的同一行 | Z11 |

也就是说 **Z9 那条断言从头到尾没被反向验证过**。报告里写的「66 处全部报出」是真的——但报出的是别的组，要验的那条从来没被碰到。这正是「注入只证明脚本有牙，前后对比/组号核对才证明它咬的是对的地方」。

修法两条：

- 把那 8 条锚点补上上下文（相邻的注释行、不同的缩进），让它们唯一
- 在 `run_reverse` 里加一条**锚点唯一性检查**：`raw[path].count(old) != 1` 直接记成问题，而不是继续注入

以后再往这些脚本里加注入，锚点不唯一会当场报出来。

## 四、验证

### 带状态模拟器（`verify_font_sim.py`，第 8 组，新增）

10 种场景（4 种文字 × 「默认卡片」/「拖到下限」，加大卡片与小卡片）：

- **对话框里选的字号真的用上了**，并且自动适应跟着关掉
- **选了大字号之后卡片长到装得下**，文字不被裁
- **字号没变时只换字体**：自动适应保持打开、字号保持原样

`--regress-dialog` 把字号丢掉（改动前的行为），复现出「选 33.1 实际是 27.1」「选 13.0 实际是 7.0」——10 种场景全部失配，断言报出。

### 源码级断言

`verify_font_library.py` 新增 **F4b 组**：`ApplyPickedFont` 必须收下 `picked.SizeInPoints`、必须走 `SetManualFontSize`、必须区分「换了字号」和「只换了字体」、必须有「只换字体就重新适应」那一支；`ChooseQuoteFont` 必须把选中的字体交给 `ApplyPickedFont`、必须用 `QuoteFont(CurrentFontSize())` 当初值。**6 条反向注入全部报出**（含锚点唯一性检查）。

`verify_size.py`：66 条注入**全部唯一且全部报出**，并逐条核对过报出的组号与预期一致。

### 自检（`XiaoJian.exe --self-test`，Windows）

新增断言 **155–162**，直接调 `ApplyPickedFont`（不弹对话框）：

- **155/156**：用当前字号再选一次 → 自动适应**仍然开着**、字号**没变**
- **157/158**：选一个大 8 磅的字号 → 自动适应**关掉**、字号**真的变成**那个值
- **159**：选了大字号之后文字仍然完整（卡片长到装得下）
- **160/161/162**：选 200 磅 → 字号长上去了、但不超过 `MaxManualFontSize`（96）、文字仍然完整

自检断言总数 157 条，最大编号 162，无重复。

### 纯逻辑工程（.NET 8）

116 项全过（这次改动不涉及纯算术，所以项数没变）。
