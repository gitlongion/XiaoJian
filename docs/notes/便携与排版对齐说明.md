# 便携式设计 + 排版对齐方式

本文说明这一版改了什么、为什么这么改，以及在 macOS 上能验证到什么程度。

---

## 一、便携式设计

原来的程序把数据放在 `%LOCALAPPDATA%\MyQuoteCard`，开机自启动写注册表。两件事都让它
**必须装在系统里**：换台电脑内容不跟着走，删程序也删不干净。这一版把这两处都改成便携做法。

### 1.1 数据目录：程序旁边优先

新增 `DataLocation`（`Storage.cs`），数据目录按**优先级**决定，只有一处做这个判断：

| 顺序 | 条件 | 目录 |
|---|---|---|
| 1 | 命令行给了 `--data-dir=<目录>` | 就用它（相对路径按程序所在目录解析） |
| 2 | 程序旁边的 `data` 文件夹**可写** | `<程序目录>\data` |
| 3 | 上面两条都不成立 | `%LOCALAPPDATA%\MyQuoteCard` |

```text
<程序所在目录>\
    MyQuoteCard.exe
    data\
        state.ini            设置
        content-1.txt        第 1 张卡片的内容库
        background-1.png     第 1 张卡片的背景图片
```

**「可写」必须真写一次才算数。** 只判断「目录能不能建出来」是不够的：Program Files 里的
目录能建出来，但里面的文件一律写不进去——那正是最需要走兜底路径的情形。所以 `TryPrepare()`
会写一个 `.write-test` 探针文件再删掉，写不进去就退回用户目录。

`--data-dir=` 指定的目录走同一套检查：路径写错、盘符不存在、目录只读，都会**退回默认位置**而不是
把程序打挂。这一段跑在程序装好自身异常兜底**之前**，在那里抛出去就是 Windows 的裸错误框，
没有任何解释。

`Program.cs` 里不再出现 `SpecialFolder.LocalApplicationData`，这个判断只有 `DataLocation` 一处，
免得两处各判一次、结果不一致——那种情况下程序照样能跑，只是悄悄不再便携。

### 1.2 升级：旧内容整份带过来

旧版所有人的内容都在 `%LOCALAPPDATA%\MyQuoteCard`。第一次以便携方式启动时，
`DataLocation.AdoptLegacyData()` 把那个目录里的文件**整份复制**到 `data` 文件夹：

- **复制而不是移动**：万一这次运行恰好是没有写权限的那次，源目录还是完整的；
- **只做一次**：`data` 里已经有 `state.ini` 就直接返回，重复启动不会反复搬；
- **不覆盖**：逐个文件 `File.Copy(..., false)`，`data` 里已有的文件一个都不动。

`Adopt(directory, legacy)` 被单独拆出来（`internal`），是因为生产入口那个版本把旧目录写死成
`%LOCALAPPDATA%`——测试没法在不碰真实用户目录的前提下验证它。拆出来之后自检和纯逻辑工程都能
拿一个假目录把三条性质（搬一次 / 不重复 / 不覆盖）都跑一遍。

### 1.3 开机自启动：改放「启动」文件夹，不写注册表

`StartupManager` 重写：

| | 旧 | 新 |
|---|---|---|
| 载体 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | 用户「启动」文件夹里的一个启动器 |
| 写入 | `CreateSubKey` + `SetValue` | `MyQuoteCard.lnk`；脚本宿主被策略禁掉时退回 `MyQuoteCard.cmd` |
| 删除 | `DeleteValue` | 删掉启动器文件（两个都删） |
| 读取 | 读注册表值 | 读启动器指向的目标 |

几个具体决定：

- **`.lnk` 优先、`.cmd` 兜底。** 快捷方式是 Windows 自己在「启动」文件夹里放的东西，启动时
  不闪控制台窗口；脚本宿主（`WScript.Shell`）被组策略关掉的环境里，一行批处理虽然难看但一定能用。
- **`.cmd` 用 `Encoding.Default` 写，不用 UTF-8。** `cmd.exe` 按 OEM 代码页读批处理文件，
  路径里有中文时 UTF-8 会变成乱码，启动直接失败。这是个只在中文路径下才暴露的坑。
- **`IsEnabled()` 仍然读一次旧注册表值。** 从旧版升级过来的用户，注册表里那条还在、还在生效，
  如果只认启动文件夹，菜单里的勾会是空的——那是在骗人。所以读，但**从不写**；用户下次动这个
  开关时顺手把旧值删掉（`RemoveLegacyEntry()`），从此与注册表再无关系。
- **`PointsAtThisProgram()` 比对 EXE 路径。** 同时留着「U 盘上一份便携的 + 装了一份」的用户，
  不比对路径就会启动错的那一份。

## 二、排版对齐方式

### 2.1 两个轴各三选一

`CardState` 新增两个字段，取值是 `AlignNear` / `AlignCenter` / `AlignFar`（0/1/2）：

```csharp
public int TextAlignHorizontal = AlignCenter;
public int TextAlignVertical = AlignCenter;
```

默认两个都居中，与旧版画面完全一致——升级不会让任何人的卡片挪位置。

菜单挂在「文字设置 → 排版对齐」下，共六项：

```text
左对齐        水平居中      右对齐
────────
顶部对齐      垂直居中      底部对齐
```

当前生效的两项打勾（在 `ApplyMenuLanguage` 里按 `_card` 的当前值设 `Checked`，
沿用「语言」子菜单已有的做法，不额外加字段）。

### 2.2 对齐只作用于绘制，绝不进入测量

这是这一版最要紧的一条约束，也是本项目**已经踩过一次**的那类坑：

> 卡片的尺寸下限与字号都由 `MeasureBlock()` 算出来。只要对齐渗进测量，
> 换个对齐方式就会改变文字块的大小 → 下限跟着变 → 卡片跟着变，
> 用户只是想「把字靠左」，卡片却自己动了。

所以实现上刻意分成两半：

- `MeasureBlock()` / `MeasureHorizontal()` / `BuildColumns()` / `FitsBlock()` **完全不看对齐**；
- 只有 `PaintHorizontal()` / `PaintVertical()` 看。

自检 114 / 115 就钉在这一点上：切一次对齐，`QuoteBlockSize` 与 `MinimumCardSize` 必须一个像素都不动。
静态断言里还有一条更直接的：这四个测量方法的函数体里**不许出现 `Alignment` 这个词**。

### 2.3 两条绘制路径

横排直接用 GDI 的排版标志（`TextFormatFlags` 没有「居中」这个标志可清——左和上是默认值，
所以「近端」那一支什么也不加）：

```csharp
TextFormatFlags.WordBreak | HorizontalFlags() | VerticalFlags() | ...
```

竖排是自绘的（逐字、列从右到左），没有现成标志可用，改成算偏移：

```csharp
int originX = TextMargin + AlignOffset(availableWidth - blockWidth, _horizontalAlignment);
int originY = TextMargin + AlignOffset(availableHeight - blockHeight, _verticalAlignment);
```

`AlignOffset()` 里 `free <= 0` 直接返回 0：文字比地方还大时，远端对齐会把文字整个推出可视区，
钉在起点至少还能看见一部分。

**竖排的「左/右」是屏幕方向，不是阅读顺序。** 竖排的列从右向左读，但用户点「右对齐」时想的是
「让文字靠卡片右边」，不是「让它回到阅读起点」。两种理解都能自圆其说，选了不会让人意外的那个。
`TextMargin` 内缩也保持一致，两种排版对「左边」的理解才一样。

macOS 上跑不了 exe，所以覆盖的是「编译 + 源码级断言 + 纯逻辑测试 + 模型仿真 + PE 结构 +
对照构建」。`sh verify_all.sh` 一次跑完 10 步：

| 步骤 | 结果 |
|---|---|
| 1. 交叉编译（net40 / AnyCPU / winexe） | 0 警告 0 错误 |
| 2. 卡片尺寸静态断言 + 反向注入 | 14 组通过；注入 34 处，报出 34 处 |
| 3. 字号与内容库静态断言 + 反向注入 | 13 组通过；注入 25 处，报出 25 处 |
| 4. **便携式与排版对齐静态断言 + 反向注入** | 3 组通过；注入 24 处，报出 24 处 |
| 5. 字号链路仿真 | 10 项通过；4 种反向注入分别报出 2 / 4 / 1 / 2 条失败 |
| 6. 退出路径静态断言 | 13 组通过 |
| 7. 纯逻辑测试工程（.NET 8，跑真实抽取代码） | **91 项通过**，0 失败 |
| 8. 拖动缩放收敛模拟 | 全部通过 |
| 9. PE / 元数据校验 | 全部结构校验通过 |
| 10. 对照构建 | 最初改动前 31 条；上一版交付 44 条 / **61 条**；本版 0 条 |

第 10 步那 61 条是本版新增断言打在**上一版交付源码**上的结果：说明这批断言不是空转，
它们咬的正是这一版新加的东西。

补丁与产物的一致性：

- `portable-and-align.patch`（基线 = 上一版交付）应用后，6 个文件与交付源码逐字节一致；
- `all-changes-v6.patch`（基线 = 上游 HEAD）应用后，7 个文件逐字节一致，且重新编译出的 exe
  与交付 exe 的**方法集合、类型集合完全相同**（350 个方法 / 30 个类型）；
- 交付 exe：`dist/MyQuoteCard.exe`，105984 字节，
  SHA-256 `84ae0adfcc8fd1001b151b23fb279fd7b35892ec04611832f09ad2f9e4f8f800`。

### 新增的自检（`MyQuoteCard.exe --self-test`，在 Windows 上跑）

- 94 / 95：对齐方式按原值往返；
- 96 / 97：新建卡片继承上一张的对齐方式；
- 98：手改配置文件里的越界对齐值被兜回三选一之内；
- 100~103：`--data-dir=` 被原样采用、目录会被建出来、`IsPortable` 认得/不认得对；
- 104~108：旧用户目录的内容整份带过来、一字不差、只带一次、不覆盖已有内容；
- 110~115：对齐真的传到了绘制层，且**文字块尺寸与卡片下限一个像素都不动**。

### 还没验证的

真机才能确认的部分：

- **启动文件夹**：快捷方式能否创建、开机是否真的启动、脚本宿主被禁用时 `.cmd` 兜底是否生效。
  这一侧只能静态断言「不写注册表」「用 `SpecialFolder.Startup`」「`.cmd` 用 ANSI 编码」。
- **不可写目录的兜底**：把 exe 放进 Program Files 或只读盘，确认真的退回用户目录、
  且探针文件没被留下。
- 拖拽缩放的收放手感、真实字体（微软雅黑 / 宋体）下的行高与折行位置、以及六种对齐方式在
  真实 GDI 下的实际观感。
