# MyQuoteCard 鼠标穿透（TopMost + Click-Through）实现说明

需求：卡片保持最顶层显示，同时让鼠标事件穿透卡片，使点击作用到下层窗口。

## 一、实现方式

新增一个可持久化的开关 `ClickThrough`（`state.ini` 里的 `ClickThrough=True/False`），通过窗口扩展样式 `WS_EX_TRANSPARENT` 让窗口对命中测试"不存在"。

### 1. 状态与入口

| 位置 | 改动 |
| --- | --- |
| `Storage.cs` `AppState` | 新增 `public bool ClickThrough`，并在 `Load` / `Save` 中读写（键名 `ClickThrough`） |
| 右键菜单 → 卡片设置 | 新增勾选项 `ClickThrough`：「鼠标穿透（点击直达下层窗口）」；因为托盘图标复用同一个 `ContextMenuStrip`，托盘右键菜单里也能开关 |
| 菜单 `Opening` | 每次打开时按 `_state.ClickThrough` 同步勾选状态 |
| 托盘 tooltip | 开启时显示「自言卡（鼠标穿透中）」，提示用户当前卡片不响应鼠标 |

### 2. 应用样式（两处，缺一不可）

```csharp
private const int GwlExStyle = -20;
private const int WsExTransparent = 0x00000020;

// ① 声明在 CreateParams：句柄重建后仍然带上该样式
protected override CreateParams CreateParams
{
    get
    {
        CreateParams parameters = base.CreateParams;
        if (_state == null || !_state.TransparentBackground) parameters.ClassStyle |= CS_DROPSHADOW;
        if (ClickThroughEnabled) parameters.ExStyle |= WsExTransparent;
        return parameters;
    }
}

// ② 运行时立即生效，避免为了切样式去重建窗口
private void ApplyClickThroughStyle()
{
    if (!IsHandleCreated) return;
    int style = NativeMethods.GetWindowLong(Handle, GwlExStyle);
    int updated = ClickThroughEnabled ? (style | WsExTransparent) : (style & ~WsExTransparent);
    if (updated != style) NativeMethods.SetWindowLong(Handle, GwlExStyle, updated);
}
```

`ApplyClickThroughStyle()` 的调用点：

- `OnHandleCreated`：任何原因导致句柄重建后自动补回（本项目 `RecreateHandle()` 出现在切换透明背景、改背景色/背景图、恢复默认外观等处，漏掉就会"穿透失效"）；
- 菜单勾选/取消时（经 `ApplyClickThroughState()`）；
- `LocateCard()` / `EndLocateCard()`：见下面第 4 点。

### 3. 同时撤掉透明模式的隐形点击层

透明模式下卡片本体靠 `TransparencyKey`（键色像素穿透）实现"只显示文字"，另有一层 `TransparentHitBoxForm` 专门接收拖动/右键/缩放。它是个普通窗口，会吃掉点击，所以开启穿透时必须隐藏：

```csharp
// UpdateTransparentHitBox() 与 PositionTransparentHitBox() 中
if (_locatingCard || _state.ClickThrough || !_state.TransparentBackground || !Visible) { ...Hide(); return; }
```

### 4. 保留"退路"（关键）

穿透后卡片收不到任何鼠标消息，因此必须保证还能关掉它：

- **托盘图标右键菜单**：主出口（卡片设置 → 鼠标穿透）；
- **`Ctrl + Alt + Q` 寻找卡片**：定位期间临时取消穿透，让找到的卡片可以立刻被抓取：

```csharp
private bool ClickThroughEnabled { get { return _state != null && _state.ClickThrough && !_locatingCard; } }

// LocateCard():      _locatingCard = true;  ApplyClickThroughStyle();   // 临时可点击
// EndLocateCard():   _locatingCard = false; ApplyClickThroughStyle();   // 恢复穿透
```

### 5. 开启穿透时顺带置顶

穿透只影响命中测试，不影响层级。如果卡片不在最上层，穿透就"看不出效果"，所以在勾选穿透时自动设为置顶：

```csharp
if (clickThroughItem.Checked && !TopMost) SetCardLayer(true);
```

## 二、所需的事件穿透配置

### 核心：`WS_EX_TRANSPARENT`

```
GWL_EXSTYLE      = -20
WS_EX_TRANSPARENT = 0x00000020   // 必需：窗口不参与命中测试，点击落到下层窗口
WS_EX_LAYERED     = 0x00080000   // 视觉透明/整体 alpha，常与之配合
WS_EX_TOOLWINDOW  = 0x00000080   // 可选：不出现在 Alt+Tab
WS_EX_NOACTIVATE  = 0x08000000   // 可选：不抢焦点（悬浮层常用）
```

`WS_EX_TRANSPARENT` 加在**顶层窗口**上即可让整棵窗口子树（含 Label 等子控件）都不参与命中测试。

### 为什么不用其它做法

| 做法 | 结论 |
| --- | --- |
| `WM_NCHITTEST` 返回 `HTTRANSPARENT` | **不够**。它只把消息转给**同一线程**的窗口，无法穿透到其它进程的窗口（本项目已有 `WM_NCHITTEST` 处理，容易误用） |
| `TransparencyKey` 键色像素 | 只让键色像素穿透。卡片透明模式正是靠它，但文字像素仍会挡住点击，做不到"整卡穿透" |
| 分层窗口（`UpdateLayeredWindow` 每像素 alpha） | alpha=0 的像素本身穿透，同样只对透明像素生效 |
| `SetWindowRgn` 挖空 | 能穿透，但被挖掉的区域也画不出内容，不适用 |
| 低级鼠标钩子转发 | 能做到"穿透且不激活下层"，但成本高、易被安全软件拦截，不建议 |

### 两个容易踩的坑

1. **不要自己加 `WS_EX_LAYERED`**：WinForms 在 `Opacity < 1` 或设置了 `TransparencyKey` 时会自动添加并调用 `SetLayeredWindowAttributes`。手工加上却不设置属性，窗口会变成**完全不可见**。本项目两种模式都满足条件（透明模式用 `TransparencyKey`，普通模式 `Opacity = 0.97`），所以无需处理。
2. **样式会随句柄重建丢失**：`SetWindowLong` 改的是当前 HWND。只要代码里存在 `RecreateHandle()`，就必须同时在 `CreateParams` 里声明样式（本实现两者都做了）。

## 三、需要注意的边界情况

1. **穿透 = 卡片彻底不可交互**：拖动、缩放、右键菜单、双击编辑全部失效。这是设计使然，所以必须有托盘菜单这条退路（已实现），编辑内容库请走托盘菜单。
2. **定位期间临时可点击**：`Ctrl+Alt+Q` / 托盘双击会临时关闭穿透并高亮 6 秒，方便抓取；6 秒后恢复穿透。
3. **子控件**：`WS_EX_TRANSPARENT` 在顶层窗口上会连带子控件一起跳过。若在某些 Windows 版本上发现文字像素仍挡点击，可对子控件再补一次：
   ```csharp
   foreach (Control child in Controls)
       NativeMethods.SetWindowLong(child.Handle, GwlExStyle,
           NativeMethods.GetWindowLong(child.Handle, GwlExStyle) | WsExTransparent);
   ```
   （注意：加在子控件上会影响其绘制顺序，建议仅在确有问题时使用。）
4. **透明模式的隐形层必须一起处理**：否则它仍会挡住点击（已隐藏）。
5. **点击会激活下层窗口**：这是 Windows 的正常行为。若要求"穿透但不激活下层"（如某些悬浮字幕），需要低级鼠标钩子，另当别论。
6. **系统级隔离**：UAC 提权窗口、独占全屏游戏、以及"以管理员身份运行"的下层窗口，普通权限的置顶窗口可能盖不住或穿不进去，属系统限制。
7. **多显示器 / DPI**：样式与 DPI 无关；DPI 变化时 WinForms 可能重建句柄，`OnHandleCreated` 会自动补回样式。
8. **穿透不影响键盘、热键、托盘与绘制**：`WS_EX_TRANSPARENT` 只改命中测试，所以 `Ctrl+Alt+Q`、托盘图标、每日刷新都照常工作。
9. **与"只让空白处穿透"的上一处修复可共存**：不开启穿透时，卡片空白处穿透、文字区域可操作；开启穿透后整卡穿透。
10. **用户忘记怎么关**：托盘 tooltip 会显示"（鼠标穿透中）"，帮助里也补了两条说明。
