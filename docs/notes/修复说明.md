# MyQuoteCard 透明点击层修复说明

修复目标：透明背景模式下，不可见的"点击层"原本覆盖整张卡片，挡住其下方窗口/桌面图标的点击。现改为**按文字内容自适应**，边界与文字区域对齐。

## 一、问题定位

| 组件 | 角色 | 命中测试行为 |
| --- | --- | --- |
| `QuoteCardForm`（卡片本体） | 显示文字 | `TransparencyKey` + `LWA_COLORKEY`：**只有文字像素可点击**，其余像素本来就穿透到下层 |
| `TransparentHitBoxForm`（隐形框架） | 给透明卡片提供拖动/右键/缩放的实体表面 | `Opacity=0.01` 的普通窗口，**整个矩形都会吃掉点击** |

`PositionTransparentHitBox()` 原本执行 `SetCardBounds(Bounds, Region)`，即把框架铺满整张卡片，所以真正挡住下层点击的是这一层，而不是卡片本身。这也解释了为什么"字体显示正常、只有点击被挡"。

## 二、改动内容

### 1. 框架尺寸按文字自适应（核心）

新增 `QuoteCardForm.QuoteHitFrameInClient()`：
用 `TextRenderer.MeasureText`（与 Label 的 GDI 绘制方式一致）测量当前文字，取文字块大小 + 6px 内边距，居中于 `_quoteLabel` 内，并夹紧到标签范围，最小 36×28（保证极短内容仍有可拖拽区域）。框架的 `Bounds` 直接取该矩形的屏幕坐标，`Region` 置空（矩形贴合，不再需要圆角裁剪）。

效果：460×190 卡片显示 3 个字时，遮挡面积从 87400 px² 降到约 7200 px²（≈92% 削减）。

### 2. 框架 → 卡片的映射（保证原有交互不变）

新增 `ApplyHitFrame(frame)`，用**增量**方式换算：

```
卡片宽 += 框架宽增量     卡片高 += 框架高增量
卡片位置 += 框架位置增量   （再夹紧到 340×140 ~ 700×320）
```

因此：

- 拖框架 = 卡片 1:1 跟随移动，尺寸不变（原行为）；
- 拖框架边缘/四角 = 卡片按相同位移缩放，且对边保持不动（与原"拖卡片边缘"完全一致）；
- 最小/最大尺寸夹紧逻辑不变。

### 3. 手势期间不回写框架位置

新增 `HitFrameOwnedByPointer()`：正在拖动、鼠标按键被按住、或处于系统移动/缩放模态循环（`WM_ENTERSIZEMOVE`~`WM_EXITSIZEMOVE`）时，`PositionTransparentHitBox()` 不再重排框架，避免与系统缩放循环互相抢矩形导致抖动。手势结束后（`UserResizeFinished` / `MouseUp`）再重新贴合文字。

### 4. 其他配套

- `FitQuoteFont()` 末尾统一调用 `PositionTransparentHitBox()`：换字号、换字体、换内容后框架立即重新贴合（原先只有换尺寸才会重排）。
- `TransparentHitBoxForm.MinimumSize` 由 340×140 放宽到 24×20（否则小框架会被夹回卡片大小，自适应失效）。
- `ResizeSupport.HitTest` 手柄宽度按框架尺寸自适应（`min(12, min(w,h)/4)`，下限 3），保证小框架仍留有拖动区；460×190 时仍为 12，自检断言不变。
- 帮助文案同步更正为"文字区域仍可右键、拖动和调整大小 / 卡片空白处不会挡住下层窗口的点击"。
- 自检新增断言（返回码 28）：透明框架必须非空、小于卡片且完全位于卡片内。

## 三、验证方式

本机为 macOS，无法编译/运行 .NET Framework WinForms，故采用：

1. **语法解析**：tree-sitter C# 解析 `Forms.cs` / `Storage.cs` / `Program.cs` / `AssemblyInfo.cs`，0 error。
2. **算术仿真**：独立 Python 复刻框架测量与映射逻辑，覆盖右/左边缘缩放、最小最大夹紧、拖动跟随、长文本/空文本、手柄尺寸，以及"系统手势消息丢失"的最坏情况，全部断言通过。
3. **仓库自检**：在 Windows 上构建后运行 `MyQuoteCard.exe --self-test`，返回 0 表示通过（新增 28 号断言）。

## 四、需要留意

- 透明模式下，可点击/可拖拽区域现在是**文字区域**（含 6px 内边距），卡片空白处点击会穿透——这正是本次修复的目标，但属于行为变化，已在帮助文案中说明。
- 若后续希望恢复"点空白也能操作卡片"，可把 `HitFramePadding` 调大，或在框架 `Region` 上追加一圈细边框（代价是会重新遮挡一小圈区域）。
- `ApplyHitFrame` 依赖 `WM_ENTERSIZEMOVE/WM_EXITSIZEMOVE` 与鼠标按键状态做手势判定；这两个信号都失效的极端情况下，缩放会因框架被反复重排而偏向放大（受 700×320 上限约束，松手后自动恢复）。
