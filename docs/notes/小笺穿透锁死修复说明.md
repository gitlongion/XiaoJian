# 第 2 张卡片开启鼠标穿透后被锁死 — 修复说明

**版本 0.9.13 · 2026-11-08**

## 现象

除第一张卡片外，新建的卡片一旦勾选「鼠标穿透」，就再也无法选中、右键打开菜单、修改字体颜色或任何其它设置。

## 根因

这不是操作问题，是程序里**真的没有入口了**。五条路径断在同一处：

| 入口 | 为什么到不了第 2 张卡片 |
|---|---|
| 托盘图标 | `CardManager.AddForm` 只在 `_forms.Count == 0` 时传 `showTrayIcon = true`。每张卡片各有自己的 `_menu` 和 `_trayIcon` 对象，托盘的 `ContextMenuStrip` 是**第一张卡片的菜单**，其中所有设置项的闭包都捕获那张卡片的 `this` |
| 卡片自己 | 穿透是窗口级的 `WS_EX_TRANSPARENT`，鼠标事件完全不进；`UpdateTransparentHitBox` 在穿透时还会 `Hide()` 掉透明点击层，右键菜单一起消失 |
| 卡片列表 | 原来每项只有 `ToggleCardVisible()`，隐藏再显示不会重置穿透 |
| `Ctrl+Alt+Q` / 双击托盘 | `EnsureHotKey()` 取第一个注册成功的窗口；托盘双击调的是托盘所属卡片的 `LocateCard()` —— 都是第一张 |
| 再次打开程序 | `TryLocateExistingCard()` 用 `FindWindow(null, "小笺")` 只给找到的**一个**窗口发消息，而所有卡片的标题都是「小笺」 |

唯一没被断掉的是键盘，但程序没有这样的快捷键（唯一的 `KeyDown` 在内容编辑器里）。

**帮助文本还在误导**：一句写着「卡片列表里可以显示、隐藏或定位每一张卡片」——代码里没有「定位」；另一句写着「请在托盘图标的右键菜单里取消勾选」——但托盘里那个勾反映的是第一张卡片的状态，显示未勾选，点一下反而把第一张卡片打开穿透。文档与实现对不上，是这个缺陷能留到现在的原因之一。

## 应急解锁（如果已经在 0.9.12 上锁住了）

1. **先退出程序**（托盘 → 退出）。必须先退出，否则程序退出时会把内存状态写回 `state.ini`，覆盖手工修改。
2. 打开程序旁边的 `data\state.ini`，第 N 张卡片对应 `Card{N-1}.` 段。
3. 把该段的 `ClickThrough=True` 改成 `False`，只改这一行，别动 `Slot`。
4. 保存，重新启动。

## 修复

改的是 `RefreshCardList` —— 它是唯一对每张卡片都有条目、又不依赖卡片能接收鼠标的菜单。

每一项从「点一下切换显示/隐藏」改成一个**子菜单**：

- **显示 / 隐藏这张卡片**：原有行为，移进子项
- **寻找这张卡片（临时可点击）**：调该卡的 `LocateCard()`，复用已有的「定位时临时摘掉穿透」机制（6 秒后恢复）
- **关闭鼠标穿透（恢复可操作）**：仅当那张卡片确实开着穿透时出现

第三项不能省。`_locateTimer` 只有 6 秒，打开取色对话框都不够；倒计时一到穿透又回来了。所以新增 `DisableClickThrough()`，一步到位：

```csharp
internal void DisableClickThrough()
{
    if (!_card.ClickThrough) return;
    _card.ClickThrough = false;
    ApplyClickThroughState();   // 摘掉 WS_EX_TRANSPARENT，恢复点击层
    _app.Save();                // 写回 state.ini，否则下次启动又锁死
    if (Manager != null) Manager.RefreshAllMenus();  // 让解锁项立刻消失
}
```

**不改托盘归属，不引入「当前卡片」概念。** 这是能解除死锁的最小改动。代价是：要改某一张卡片的设置，仍需右键那张卡片本身（或先「寻找」让它临时可点击）。

三个动作全部放在 `RunAfterMenu` 里——`RefreshAllMenus()` 会重建这些菜单项，在菜单点击消息里直接做会拆掉正在处理自己的对象。

帮助文本中英文四句同步改正。

## 顺带修的两处

- `app.manifest` 的 `assemblyIdentity version` 一直停在 **0.7.0.0**（程序集已是 0.9.13.0）。
- 加了版本一致性断言：`verify_exe.py` 现在拿 exe 的真实程序集版本当基准，检查 `VERSION`、`AssemblyInfo.cs`、`app.manifest`、README 里的下载文件名四处。升版本改漏一处既不报编译错误也不影响运行，只能靠断言发现；顺带也能抓住「源码改了但没重新编译」。

## 一个交互变化

原来点一下卡片条目就切换显示/隐藏，现在要先展开子菜单再选。这是为三个动作腾位置的代价；隐藏本就不是常用操作，而「寻找」和「解锁」是这次要补的。

## 仍然验不了的

Windows 上真实的下拉菜单交互（子菜单展开、点击后菜单是否正确关闭）、`WS_EX_TRANSPARENT` 摘除后立即右键是否真的能收到消息、多显示器下第 2 张卡片的定位落点。这些只能在真机上确认。
