## 一、圆角路径没守边界（用户能从菜单直接踩到）

```csharp
int diameter = radius * 2;          // 原来
path.AddArc(bounds.Left, bounds.Top, diameter, diameter, 180, 90);
...
```

半径先被 `CornerRadiusFor` 按**窗口尺寸**夹过一次，但真正画的矩形比窗口小一像素，粗边框还要再往里让半个笔宽。于是：

| 情形 | 后果 |
|---|---|
| 38×38 的小卡片选「很圆」（半径 40 → 夹到 19） | 直径 38 > 矩形 37，上边两个弧互相覆盖，路径在角上**翻折** |
| 选「直角」（半径 0） | 四个零尺寸的弧退化成**四个重合点** |

修法是把直径直接夹在被画的矩形里，半径 0 时退回矩形路径：

```csharp
int diameter = Math.Min(radius * 2, Math.Min(bounds.Width, bounds.Height));
if (diameter <= 0) { path.AddRectangle(bounds); return path; }
```

**为什么放在 `RoundedRectangle` 里而不是调用处**：这个函数有两个调用点（画边框、以后可能还有别的），把「半径不能超过矩形」写进函数本身，调用方就不用各自记得。而且夹在函数里对任何输入都成立，不需要知道调用方是不是已经夹过一次。

自检 264–267 直接调它：半径 0 要得到 4 个点的矩形路径，半径 40 画在 37×37 上要得到边界不超过 37 的路径。**这两条在修复前都会失败**（一个是退化路径，一个是边界跑到 −43..80）。

## 二、两个数据文件都是原地写（崩溃就丢内容）

```csharp
File.WriteAllLines(_path, lines.ToArray(), ...);   // 原来
```

`state.ini` 和每张卡片的内容库都是**整份重写**，每次改动都重来一遍。原地写意味着写到一半崩溃、磁盘满、断电，就留下一个**截断的文件**——而内容库截断就是用户写的句子没了。

新增 `AtomicFile`：先写同目录的 `.tmp`，再用 `File.Replace` 一步换名。

```csharp
File.WriteAllText(temp, contents, new UTF8Encoding(false));
File.Replace(temp, path, null);      // 旧文件被删、新文件顶替，一步完成
```

`File.Replace` 在文件被杀毒软件或外壳扩展占着时会抛异常，那时退回整份复制——不是原子的，但 `.tmp` 已经写完整，**失败也只是这次没保存，原文件仍然可读**，比丢失全部内容好。

## 一个值得记下来的判断

这两处都不是「写错了」，是**没考虑到某个输入**。而它们的共同点是：**输入范围是用户能直接选到的**——「直角」和「很圆」就在菜单里，磁盘满也不是理论情况。

所以复查时最该问的不是「这段代码对不对」，而是「**它假设了什么，这个假设能不能被打破**」。圆角函数假设了「半径一定小于矩形」，写盘假设了「这次写入不会中途失败」——两个假设都不成立。
