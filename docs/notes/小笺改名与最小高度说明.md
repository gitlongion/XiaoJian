# 小笺 · XiaoJian —— 改名与最小高度

版本 0.7.0。两件事：**卡片的最小高度不再有那个固定下限**，以及**软件改名为「小笺」**。

---

## 一、最小高度：那 40 像素是给一个从不显示的标签留的

> 卡片背景最小高度还是有固定限制无法调整更小

### 问题在哪

一张只放一行小字的卡片，怎么拖都停在 56 像素高。两个地方一起钉住了它：

| 位置 | 原来 | 作用 |
|---|---|---|
| `CardSizeLimits.VerticalMargin` | `40`（`LayoutCard()` 上下各内缩 20） | 文字视图比卡片矮 40 |
| `CardState.MinCardHeight` | `56` | 退化态下限 |

一个汉字在最小字号（7 磅）下约 12 像素高，加上 `TextSlack = 4`，正好是 `12 + 4 + 40 = 56` ——
两个数字在同一个位置上重合，所以怎么改都还是 56。

那 40 里的**下面 20 像素**是给 `_dateLabel` 留的。而 `_dateLabel` 是构造函数里
`Visible = false` 建出来的，之后**再也没有被打开过**。把旧源码翻一遍，它一共出现 13 次：

```
声明(1) 构造与设置(8: 尺寸/背景/前景/字体/对齐/光标/Visible=false/加进 Controls)
ContextMenuStrip(1) AttachDragHandlers(1) LayoutCard 里的 SetBounds(1)
```

`_dateLabel.Text` **一次都没被赋过值**。也就是说：一个从没写过内容、从没显示过、却照样被
摆好位置、挂上右键菜单、接上拖拽的标签 —— 上一版留下的死重量。每张卡片都比自己的文字高出
20 像素，只为了一块永远空着的区域。

### 改法

上下内边距从 20 减到 12，`MinCardHeight` 从 56 减到 32，`_dateLabel` 整块删掉。

```
TextPadLeft   = 32      // 左右不动：留出圆角，右侧还给右下角的「⋯」按钮留位置
TextPadRight  = 32
TextPadTop    = 12      // 原来是 20
TextPadBottom = 12      // 原来是 20，整条都是给日期标签留的
HorizontalMargin = TextPadLeft + TextPadRight    // 64
VerticalMargin   = TextPadTop + TextPadBottom    // 24，原来是一个写死的 40
```

左右**故意不动**。它们不只是留白，还承担着两件事：把文字从圆角边缘推开，以及给右下角的
「⋯」按钮留位置 —— 按钮横向占 `W-56 … W-22`，文字视图右边界在 `W-32`，所以按钮有一半压在
文字视图的右下角上，一半落在右侧留白里；它是半透明的灰色，本来就是**盖在角落上**的，不是
另起一栏。

`MinCardHeight` 取 32 而不是「刚好等于一行文字的高度」，是有意的：它必须**低于**真实下限，
否则它自己就变成一个新的固定限制。真实下限由文字算出来（`CardSizeLimits.MinimumFor`），
一个字都没有的时候才落到这个退化态。

### 结果

| 文字 | 旧下限 | 新下限 | 高度 |
|---|---|---|---|
| 4 字 | 89×66 | **107×39** | −27 px |
| 10 字 | 120×66 | **120×50** | −16 px |
| 26 字 | 137×88 | **158×61** | −27 px |
| 50 字 | 170×99 | **170×83** | −16 px |

宽度有两处反而变宽了，这是对的：下限取的是**面积最小**的那个候选，而旧的 `MinCardHeight = 56`
把好几个候选的高度都抬到 56、压平了面积曲线，于是最窄的那个赢了。下限降下来之后面积曲线恢复
了它本来的形状，`4 字` 从 5874 降到 4173 平方像素、`26 字` 从 12056 降到 9638 —— 卡片整体更小了，
只是不再是「最窄的那一条」。

### 「⋯」按钮怎么办

按钮在右下角，从卡片右下两个边量过来：右 56、下 43，尺寸 34×28 —— 这几个数字就是从旧代码
`_menuLabel.SetBounds(ClientSize.Width - 56, ClientSize.Height - 43, 34, 28)` 里提出来的，只是
现在有了名字。

问题在于旧代码**没有夹住它**：卡片高度是 56 时按钮顶端落在 `56 - 43 = 13`，正好在文字上方那
一行留白里；下限降下来之后，39 像素高的卡片上顶端变成 `-4`，按钮整个挂到卡片外面去；高度在
43 到 55 之间时它又会**盖在文字上**。所以下限一降，就必须给它一条规矩：

```csharp
public const int MenuButtonMinCardHeight = MenuButtonBottomInset + SmallestLineHeight; // 43 + 12 = 55
```

卡片高度低于 55 时按钮不显示，同时位置被夹在卡片内部（`MenuButtonBounds` 里对宽高都取了 `Math.Min`）。
这只是一个**显示阈值**，不参与「卡片能有多小」的计算 —— 下限是文字的足迹，按钮没有资格改它。

菜单本身没有丢：卡片上**右键**任意位置能打开同一个菜单，托盘图标也能。而且旧下限就是 56，
所以**没有任何一张本来存在的卡片会因为这条规则失去按钮**。

### 顺带修掉一个被旧下限盖住的洞

`MinimumFor` 的候选循环里加了一条守卫：

```csharp
if ((vertical ? block.Height : block.Width) + TextSlack > probe) continue;
```

一个候选只有在「用来量它的那个视图真的装得下量出来的块」时才可用。竖排最容易被踩到：列数由
高度决定，探针触底时视图比一个字还矮，而量出来的块仍然是一个字高 —— 按它算出来的卡片会裁掉
自己的文字。**旧的 56 像素退化态下限一直在替这个洞兜底**，所以它从没暴露过；下限一降下来，
`verify_shrink_sim.py` 立刻在「竖排 1/2/4 字」上报出「停下时文字却被裁掉了」。

这条值得单独记一笔：**降低一个退化态下限，会把原先被它盖住的潜在缺陷一起掀开**。下限不是
「保守一点更安全」，它是一块遮布。

## 二、改名：小笺 · XiaoJian

软件已经和上游的 `oocreater/MyQuoteCard` 相差很远了 —— 便携式数据目录、多卡片、竖排、字号
手动档、对齐、任意尺寸，托盘与热键全都重写过。继续叫原来的名字会误导人，所以改名。

| | 原来 | 现在 |
|---|---|---|
| 名字 | MyQuoteCard / 自言卡 | **小笺 / XiaoJian** |
| 版本 | 0.6.1 | **0.7.0** |
| 可执行文件 | `MyQuoteCard.exe` | `XiaoJian.exe` |
| 命名空间 | `MyQuoteCard` | `XiaoJian` |
| 单实例互斥体 | `Local\MyQuoteCard.SingleInstance.*` | `Local\XiaoJian.SingleInstance.1A7C4B92` |
| 异常日志 | `MyQuoteCard_error.log` | `XiaoJian_error.log` |
| 程序集 / 清单标识 | `MyQuoteCard.app` | `XiaoJian.app` |
| 自启动快捷方式 | `MyQuoteCard.lnk` / `.cmd` | `XiaoJian.lnk` / `.cmd` |

互斥体名字跟着改了，这是有意的：新旧两个 exe 同时开着时会被当成两个程序（各弹一张卡片）。
升级的正常做法是用新 exe 换掉旧的，换完之后单实例照旧；如果两个 exe 都留在文件夹里，那是
用户自己选择了同时跑两个。

### 升级不能踩的坑：这些名字必须留着旧的

改名最危险的地方不是改错，而是**把老用户的东西改没了**。下面这些名字**故意保留旧名，而且只读**：

| 保留的旧名 | 为什么 |
|---|---|
| 注册表值名 `MyQuoteCard` | 旧版把自启动写在这里。只读它、只在关闭自启动时删它 —— 本程序**完全不写注册表** |
| 用户目录 `%LOCALAPPDATA%\MyQuoteCard` | 旧版把设置、内容库、背景图放这里。升级时要整份搬到程序旁边的 `data` |
| 启动方式 `MyQuoteCard.lnk` / `MyQuoteCard.cmd` | 旧版放在「启动」文件夹里的那两个文件 |
| 可执行文件名 `MyQuoteCard.exe` | 判断「这个启动方式是不是指向我自己」时，旧名也要认 |

新增了 `StartupManager.CarryOverLegacyLauncher()`，开机时跑一次：

```csharp
public static void CarryOverLegacyLauncher()
{
    bool ours = PointsAtThisProgram(ShortcutTarget(LegacyShortcutPath)) ||
        PointsAtThisProgram(CommandTarget(LegacyCommandPath));
    if (!ours && !File.Exists(LegacyShortcutPath) && !File.Exists(LegacyCommandPath)) return;
    if (ours) SetEnabled(true);          // 用新名字重写一份，指向现在的 exe
    DeleteQuietly(LegacyShortcutPath);   // 旧文件删掉，否则它指向一个已经不存在的老 exe
    DeleteQuietly(LegacyCommandPath);
}
```

没有这一步的话，用户升级之后开机自启动会**静默失效**：启动文件夹里那个 `MyQuoteCard.lnk` 仍然
指向 `MyQuoteCard.exe`，而那个文件已经没有了。Windows 不会报错，只会什么都不发生。

顺带一提，注册表那条也只在「用户主动关闭自启动」时才删，升级本身不会去动它 —— 免得用户只是想
试试新版、结果自启动被悄悄关掉了。

### 没有改的

README 里的 `github.com/oocreater/MyQuoteCard` 保持原样，那是上游仓库地址，不是本程序的名字。

### 验证工具这一轮的两处修正

- `verify_shrink_sim.py` 与 `verify_font_sim.py` 的边距常量**改成从真实源码里读**。写死的副本会
  悄悄过期：这一版把纵向边距从 40 改成 24、退化态高度从 56 改成 32，模拟器要是还用老数字，它
  造出来的「拖到下限」卡片会比真实下限高出 40 像素，`verify_font_sim.py` 第 2b 组「在恰好包住
  文字的卡片上点『大一点』必须生效」就名不副实了。
- `verify_shutdown_path.py` 新增两条注入：日志文件改回旧名、以及**兜底路径换了另一个文件名**。
  第二条是真的会漏：`WriteErrorLog` 有两个候选目录（exe 旁边、临时目录），只改名其中一处时，
  「旧名还在不在」这种检查是发现不了的，得数文件名出现的次数。

## 四、仍然需要在 Windows 上确认

macOS 验不了的部分：

- 拖拽缩放的**手感**（模拟器只验收敛与不裁字，验不了鼠标跟手）
- 把卡片拖到 39 像素高时**「⋯」按钮的消失与右键菜单**是否都好用
- 「启动」文件夹里的旧 `MyQuoteCard.lnk` 被改写成 `XiaoJian.lnk` 的实际结果
- 任务栏图标、托盘图标、以及 `XiaoJian.exe` 的文件属性里显示的名称
