# 多卡片 + 中文竖排 实现说明

在原有单卡片版本上新增两项能力：**同时摆放多张互相独立的卡片**，以及**中文竖排文字**（字直立、自上而下、列从右向左）。每张卡片还可以单独选择内容来源。

---

## 一、使用方式

所有入口都在**卡片的右键菜单**里（托盘图标右键是同一份菜单）：

| 菜单项 | 位置 | 作用 |
|---|---|---|
| 新建一张卡片 | 主菜单（编辑内容库下方） | 新增一张卡片，新卡片继承上一张的外观与竖排设置，位置偏移 36px，内容从每日轮换开始 |
| 卡片列表 | 主菜单 | 列出每一张卡片（带当前文字摘要与勾选状态），点击可显示/隐藏该卡片 |
| 删除这张卡片 | 主菜单 | 删除当前卡片；只剩一张时该项自动隐藏 |
| 竖排文字 | 文字设置 | 开关竖排，立即重排并重新适配字号 |
| 内容来源 → 跟随每日轮换 | 文字设置 | 从共享内容库每日轮换（默认） |
| 内容来源 → 固定显示某一句… | 文字设置 | 弹出单行输入框，把这句钉在这张卡片上 |

托盘图标提示文字会显示卡片总数与隐藏数量；`Ctrl+Alt+Q`、托盘双击仍是"寻找卡片"。

**竖排效果**：`一二三四五` 在每列 2 字的卡片里排成三列，阅读顺序为右→左，屏幕上从右往左依次是 `一二`、`三四`、`五`。文字里显式换行会强制开新列。

## 二、实现方式

### 1. 数据模型（`Storage.cs`）

原来所有状态都平铺在 `AppState` 上，现在拆成两层：

- **`CardState`**（新增，每张卡片一份）：`X`/`Y`/`CardWidth`/`CardHeight`、`TopMost`、`ClickThrough`、`TransparentBackground`、颜色、`FontName`/`FontStyleValue`/`FontAdjustment`、`BackgroundImagePath`、`AutoFitText`，以及本次新增的 `VerticalText`、`ContentMode`（`Daily`/`Fixed`）、`FixedText`、`Visible`，外加该卡片自己的当日轮换状态 `TodayDate`/`TodayQuote`/`LastQuote`。
- **`AppState`**（应用级）：`UiLanguage`、`ParagraphMode`、开机启动状态、提示状态、版本迁移号，加一个 `List<CardState> Cards`。

`DailyQuotePicker` 从 `(AppState, QuoteRepository)` 改成 `(AppState, CardState, QuoteRepository)`：固定模式的卡片直接返回 `FixedText`（为空时返回提示语），完全不碰内容库，也不会写当日轮换状态。

### 2. 持久化格式与迁移

`state.ini` 现在写成：

```
UiLanguage=...
ThemeDefaultVersion=...
...
CardCount=3
Card0.X=310
Card0.Y=88
Card0.VerticalText=True
Card0.ContentMode=1
Card0.FixedText=<base64>
...
Card1.X=...
```

- **旧文件自动迁移**：文件里没有任何 `CardN.*` 键时，把旧的扁平键（`X`、`CardWidth`、`FontName`、`TodayQuote`…）读成第一张卡片，位置、外观、开关、当日内容一个不丢；`UiLanguage`/`HintShown` 这类键本来就属于应用级，照旧读入。
- `CardCount` **只写不读**：卡片列表由 `CardN.*` 键推导，比信任一个计数更稳；`CardCount` 保留只是方便人直接看文件。
- 字符串字段继续用 base64 编码（沿用原有约定），布尔与数字用 `bool.Parse`/`int.Parse`。

### 3. 竖排排版与渲染

分成"纯算术"和"绘制"两层，前者可单独测试：

- **`VerticalTextLayout`**（纯逻辑，不依赖窗口）
  - `CharactersPerColumn(可用高度, 字高)` → 每列能放几个字，至少 1
  - `SplitColumns(文本, 每列字数)` → 按阅读顺序切列；显式换行强制开新列
  - `Truncate(列, 最大列数)` → 超出时保留前 N 列，最后一列末尾换省略号
- **`QuoteView : Control`**（自绘控件，替换原来的 `Label`）
  - 横排：`TextRenderer.DrawText` + `WordBreak | HorizontalCenter | VerticalCenter | EndEllipsis`，行为与原来的 `Label` 一致。
  - 竖排：逐字绘制。先由文本中最高/最宽的字形与一个「字」样本取较大值定出**字格**（避免纯拉丁文本塌成过密的网格），再按可用高度切列，列按**从右到左**排布，每列内自上而下。
  - 字**保持直立**，不做 90° 旋转——这是中文竖排与 GDI+ `DirectionVertical` 的关键区别。
  - `MeasureBlock()` 返回文字实际占用的像素块，`FitsBlock(font)` 判断某个字号是否放得下。

**一处重要的复用**：字体自适应（`FitQuoteFont`）和隐形点击框（`QuoteHitFrameInClient`）现在都调用 `QuoteView` 的同一个测量方法。原来这两处各用一套测量（GDI+ `MeasureString` 量字号、GDI `MeasureText` 量点击框），竖排之后如果继续各算各的，点击框就会和文字错位。

### 4. 多窗口管理

新增 **`CardManager`**：持有全部 `QuoteCardForm`，负责新建/删除/显示隐藏、托盘图标归属、以及热键指派。

- **托盘图标只有一个**，由第一张卡片持有；该卡片被删除时，图标自动交给剩下的第一张卡片。
- **`Ctrl+Alt+Q` 热键**：同一个进程里同一个热键只能被一个窗口注册成功。因此每张卡片在创建句柄时都尝试注册，先成功者持有；任何一张卡片被删除后，管理器会重新依次尝试，保证热键不会随某张卡片的消失而失效。
- **程序入口改为 `Application.Run()`**（没有主窗体）。原来用 `Application.Run(form)`，关闭那个窗体就等于退出程序，多卡片下会导致"删掉第一张卡片就退出"。退出统一走菜单里的 `Application.Exit()`。

### 5. 菜单与对话框

- 卡片右键菜单新增 `NewCard` / `CardList` / `DeleteCard`，文字设置里新增 `VerticalText` 与 `ContentSource`（`ContentDaily` / `ContentFixed`）。
- 卡片列表的条目是动态生成的（名字形如 `CardEntry0`），没有固定的 `Name`，因此 `ApplyMenuLanguage` 不会改写它们；列表在每次菜单打开时重建，并显式 `Dispose` 掉旧条目，避免长会话里菜单项堆积。
- 固定内容用新增的 `TextInputForm`（单行输入 + 确定/取消，跟随界面语言）。

## 三、需要注意的边界情况

- **最后一张卡片不能删**：`AppState.RemoveCard` 在只剩一张时返回 `false`，菜单项也会隐藏。否则程序会没有窗口可操作。
- **固定模式下"切换到另一条内容"置灰**：固定卡片没有可轮换的内容。若在固定模式下调用 `PickAnother()`（例如代码路径），它会把这卡片切回每日轮换再取一条——这是刻意的"退路"语义。
- **隐藏状态会持久化**：手动隐藏的卡片重启后仍是隐藏的，靠托盘"卡片列表"恢复；托盘提示会写明"N 张已隐藏"。
- **新建卡片继承的是外观，不是内容来源**：新卡片始终从每日轮换开始，避免新建出一张空白（固定文本为空）的卡片。
- **竖排对拉丁字母不做旋转**：每个字符占一格、保持直立。这是有意简化——真正的西文竖排需要把拉丁字母整体旋转 90°，混排时观感复杂。中日韩文本是主要场景。
- **竖排下的字格按文本内容动态计算**：同一段文字在只有中文、还是中英混排时，字格宽度可能不同，因此切换字体/内容后字号会重新适配一次。
- **`QuoteView` 是自绘控件**：它用 `SupportsTransparentBackColor` + `BackColor = Transparent` 保持原来的透明背景行为（透明模式下只有文字像素可点击）。这是与 `Label` 行为差异最大的一处，建议在真机上重点确认。

## 四、验证情况

本机是 macOS，**无法运行 Windows 窗体程序**，因此做了以下几层验证：

| 验证 | 结果 |
|---|---|
| 交叉编译（Roslyn + .NET Framework 4.0 参考程序集） | **0 警告 0 错误** |
| 纯逻辑真实执行（抽取 `AppState`/`CardState`/`QuoteRepository`/`DailyQuotePicker`/`VerticalTextLayout`，在 .NET 8 上跑） | **51 项断言全部通过** |
| 状态键名一致性（`AppendCard`/`ApplyCardField`、`Save`/`ApplyGlobalField`） | 卡片字段 21 个、全局字段 7 个，**一一对应** |
| 对照构建（用上游源码跑同一套流程） | 上游 168 方法 / 新版 240 方法；`CardState`/`CardManager`/`QuoteView`/`VerticalTextLayout`/`TextInputForm` 五个新类型**只在新版出现** |
| exe 结构（PE 头 / COR20 / 资源 / 程序集引用 / 元数据） | 全部通过；`Flags=0x1`（标准 AnyCPU），引用 5 个程序集均为 `4.0.0.0` |
| 补丁可应用性（独立 `git worktree`） | `all-changes-v2.patch` 一次性应用后 5 个文件**逐字节一致**；`hitframe-fix.patch` + `multi-card-vertical-text.patch` 依次应用同样一致 |

纯逻辑验证覆盖的是：新文件默认值、内容库去重、每日轮换、保存/加载往返、**多卡片新建与字段独立**、**删除到最后一张被拒**、**固定内容模式**、**旧格式迁移**、一次性版本迁移、**竖排分列与截断**。

**未验证（需要在 Windows 真机上确认）**：

- 竖排文字的实际观感（字格大小、列间距、居中位置是否美观）；
- `QuoteView` 作为自绘控件的透明背景表现（透明模式下点击是否只落在文字上）；
- 多窗口的托盘菜单、卡片列表、`Ctrl+Alt+Q` 热键转移；
- 内置自检 `MyQuoteCard.exe --self-test`（新增断言 34~63，其中 16~33、59~63 依赖真实窗口，本机跑不了）。

建议在 Windows 上先跑一次 `MyQuoteCard.exe --self-test`（返回 0 即通过），再实际新建几张卡片、切换竖排看看效果。
