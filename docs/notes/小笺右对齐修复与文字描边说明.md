# 右对齐为什么偏了，以及文字描边

版本 0.9.6。

## 一、右对齐：量出来的比画出来的宽

0.9.5 加了字距。字距进了两处：

- `LineWidth` —— 算「这一行有多宽」时，每个字符加上 `letterGap`
- `TextLines.Split` —— 断行时也用带 `letterGap` 的宽度

但**绘制还是整串一次画**：

```csharp
TextRenderer.DrawText(graphics, line, Font, new Rectangle(originX, ...), ForeColor, ...);
```

而 Windows 画整串时**按字形自己的步进排，根本不加字距**。

于是：

| | 宽度 |
|---|---|
| 算出来的（`LineWidth`） | `Σ字宽 + (n-1) × 字距` |
| 画出来的（GDI） | `Σ字宽` |
| 差 | `(n-1) × 字距` |

对齐是 `originX = TextMargin + AlignOffset(available - width, alignment)`：

- **右对齐**：`offset = available - width`，宽度多算了多少，文字就往左偏多少
- **居中**：偏一半，不明显
- **左对齐**：`offset = 0`，**完全看不出来**

所以症状正好是「右对齐有问题」——而且只在字距 > 0 时出现。默认 0% 时量画一致，看不出来。

### 修法：逐字绘制

```csharp
for (int position = 0; position < line.Length; position++)
{
    char character = line[position];
    if (character != ' ' && !char.IsControl(character))
        DrawGlyph(graphics, character.ToString(), x, y, stroke);
    x += Advance(character, Font) + letterGap;
}
```

这样一来**画出来的宽度严格等于 `LineWidth`**：

- 第 i 个字符画在 `originX + Σ_{j<i}(字宽_j + 字距)`
- 最后一个字符的右边缘 = `originX + Σ字宽 + (n-1)×字距` = `originX + LineWidth`

对齐落在算出来的位置上，三种对齐都准。**字距也才真的看得见**——之前它只影响断行和块宽，不影响字形位置。

代价：西文失去字偶距（kerning），字会略微松一点。这是能加字距的唯一办法——GDI 画整串时没有任何「加一点间距」的入口。

## 二、文字描边

透明背景或配了背景图片时，文字容易和壁纸糊在一起。加一圈描边就分得开了。

菜单：文字设置 → 文字描边 ▸ 无 / 细 / 中 / 粗（0 / 4% / 8% / 12% 行高）。

### 为什么是「画八次」而不是 `GraphicsPath`

GDI+ 有真正的描边路径（`GraphicsPath.AddString` + `DrawPath`），但它**用 GDI+ 渲染**，而其余文字是 GDI 渲染的——开了描边的字会跟没开的不一样，同一张卡片上两种渲染风格并存。

所以描边 = **同一个字形在周围画八圈，最后把文字本身画上去**：

```csharp
for (int distance = 1; distance <= stroke; distance++)
    for (int dx = -1; dx <= 1; dx++)
        for (int dy = -1; dy <= 1; dy++)
        {
            if (dx == 0 && dy == 0) continue;
            TextRenderer.DrawText(graphics, glyph, Font, new Point(x + dx * distance, y + dy * distance), halo, GlyphFlags);
        }
TextRenderer.DrawText(graphics, glyph, Font, new Point(x, y), ForeColor, GlyphFlags);
```

`distance` 那层循环是必要的：只按 `stroke` 画一圈，粗描边中间会漏。所以代价是 `8 × stroke` 次绘制——细是 8 次，粗是 24 次。这是显式开启才有的开销。

### 颜色跟着卡片走

```csharp
public static int OutlineColorArgbFor(CardState card)
{
    if (!card.TransparentBackground && string.IsNullOrEmpty(card.BackgroundImagePath))
        return card.BackgroundColorArgb;
    return Brightness(card.TextColorArgb) >= 140 ? 黑 : 白;
}
```

- **纯色卡片**：描边用背景色 → 和卡片同色，看不见，也就不会改变观感
- **透明背景 / 背景图片**：按文字明暗取白或黑 → 一圈光晕，把文字和背后的东西分开

### 描边算进「文字需要多少地方」

描边长在字形**外面**，所以块要变大：

- `MeasureHorizontal`：宽高各加 `2 × stroke`
- `MeasureCell`（竖排）：`cellWidth` / `cellHeight` 各加 `2 × stroke`
- 断行用的可用宽度要减掉 `2 × stroke`（`TextAreaWidth`）

开了描边，卡片会跟着长到装得下，字号也会略微回缩。和其它文字设置走的是同一条三步：`FitQuoteFont` → `GrowCardToText` → `BackOffToFittingSize`。

## 三、验证

### 源码级断言（`verify_font_library.py`，新增 F16 组）

**专治右对齐的那几条**：

- `PaintHorizontal` 里**不许再出现** `TextRenderer.DrawText(graphics, line,` —— 出现了就是又整串画，右对齐会再偏
- 必须有 `for (int position = 0; position < line.Length; position++)`
- 逐字前进必须是 `x += Advance(character, Font) + letterGap;`（少了字距，画的宽度又和算的对不上）

描边那几条：`DrawGlyph` 必须按距离逐圈、八方向、最后用文字色画字形；`MeasureHorizontal` / `MeasureCell` 必须把 `OutlinePixels(font) * 2` 算进去；字段/夹取/保存/读取/颜色五处；菜单四档的标题；`MarkCurrent`；构造函数与外观变化两处接线；`SetTextOutline` 必须重新适应。

## 四、这一轮踩的坑（值得记）

**改一处代码，打断三处老锚点。** 这一轮改了 `PaintHorizontal`（整串 → 逐字）、`MeasureHorizontal`（加描边）、构造函数（加两行），结果打断了：

| 断言/注入 | 为什么断 |
|---|---|
| P3 构造序列 | 中间插进了描边两行 |
| P3「对齐渗进测量」 | `MeasureHorizontal` 里那两行被描边改写了 |
| P3 两条对齐注入 | `originX` / `originY` 的表达式变了 |

而且 `verify_font_library.py` 的 F15 有一条**弱断言**：只查 `"_letterSpacingPercent"` 这个字段名是否出现在 `MeasureCell` 里。去掉整个算式之后字段名还在，断言照样「过」——是反向注入把它抓出来的。现在改成查完整算式。

> **断言要查算式，不要查字段名。** 字段名只能证明「这个设置被读到了」，证明不了「它被用上了」。

## 五、仍然验不了的
