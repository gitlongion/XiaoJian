# 字体预设：把一套文字样式存成名字

版本 0.9.7。第二档的最后一项。

## 一、它是什么

「文字设置 → 字体预设 ▸」三项：

```
保存当前文字样式…
─────────────
宋体小标题            ← 点一下套到当前卡片
楷体竖排味
─────────────
删除预设 ▸ 宋体小标题
            楷体竖排味
```

没有预设时，子菜单里只有一条灰掉的「（还没有预设）」和「保存当前文字样式…」。

**同名再存一次就是覆盖**——改完再存一遍就是编辑，不需要单独的「重命名」或「更新」。

## 二、预设里装什么

| 装 | 不装 |
|---|---|
| 字体名、字形（粗/斜/下划线/删除线） | **竖排** |
| 字号：自动适应开关、手选字号、自动字号上限 | **排版对齐**（两轴） |
| 文字颜色 | 卡片背景、卡片尺寸 |
| 行距、字距、文字描边 | 内容、位置、层级 |

**为什么不带竖排和对齐**：那两样属于「这张卡片怎么排」，不是「这套字长什么样」。一张竖排卡片和一张横排卡片应该能共用一个预设——把它们也存进去，预设就只能用在同一种排法的卡片上，价值立刻减半。

**为什么字号要带「自动适应」这个开关**：`ApplyTo` 里有一句

```csharp
card.ManualFontSize = AutoFitText ? 0f : ManualFontSize;
```

从一张「自动适应」的卡片存下来的预设，套到别的卡片上仍然自动适应——**不会把当时那张卡片的字号硬塞过去**。否则套一次预设，那张卡片就再也不自动适应了，而且用户完全看不出是预设干的。

## 三、预设是整个程序共用的

`AppState.Presets`，不是 `CardState` 里的东西。理由很直接：**预设的意义就是套到别的卡片上**。存在卡片里，每张卡片各有一份同名的预设，那就不是预设了。

存盘键是 `PresetCount=N` + `Preset0.Name=…` + `Preset0.FontName=…`，和卡片那套（`Card0.*`）同一个解析方式，但前缀不同，互不干扰。

`TryParsePresetKey` 要求 `Preset` 后面必须跟数字，所以 `PresetCount` 不会被当成 `Preset` 的一个字段。

## 四、菜单每次打开都重建

预设的名字是用户自己起的，**语言表里没有**，所以不能走 `ApplyMenuLanguage` 那一套。`RefreshPresetMenu()` 在每次 `menu.Opening` 时把子菜单整个清掉重建：

```csharp
while (_presetMenu.DropDownItems.Count > 0)
{
    ToolStripItem stale = _presetMenu.DropDownItems[0];
    _presetMenu.DropDownItems.RemoveAt(0);
    stale.Dispose();      // 和卡片列表一样：移除要 Dispose，不是只丢掉引用
}
```

两个列表（应用 / 删除）都用预设名当标题，所以标题有两处。

## 五、套用预设之后

`ApplyPreset` 走的是和其它文字设置同一条三步：`FitQuoteFont` → `GrowCardToText` → `BackOffToFittingSize`。

有一处特意**没有**走 `ApplyAppearance`：颜色。

```csharp
// The preset's colour is used as saved. ApplyAppearance would run the readability
// guard first, which silently overrides a low-contrast choice - and "the preset did not
// apply" is exactly what that looks like.
ForeColor = SafeColor(_card.TextColorArgb, Color.Black);
_quoteView.ForeColor = ForeColor;
_menuLabel.ForeColor = Color.FromArgb(175, ForeColor.R, ForeColor.G, ForeColor.B);
```

`ApplyAppearance` 里有 `EnsureReadableTextColor()`：文字和背景亮度差小于 70 时会把文字改成纯黑或纯白。对「换背景色」那是对的；对「套用预设」就变成了**悄悄改掉用户刚选的样式**——表现和「预设没生效」一模一样。所以预设的颜色按存的用，只把派生出来的那几份（窗体 `ForeColor`、「⋯」按钮的颜色）刷新掉，不留旧值。

## 六、验证

### 自检（Windows）

新增断言 **194–210**：

- **194–200**：套用之后字体名、字形、自动字号上限、文字颜色、行距、字距、描边逐项到位
- **201–202**：**竖排与对齐没被动过**（预设不该管这两样）
- **203**：套用之后文字仍然完整装得下
- **204–205**：预设里是「自动适应」时，套过去仍然是自动适应、手选字号被清零
- **206–210**：预设跨重启还在，名字、字体名、行距、描边都对

自检断言总数 200 条，最大编号 210，无重复、无缺号。

### 源码级断言（`verify_font_library.py`，F17 组）

- `TextPreset` 存在；`ApplyTo` 必须带过去七样，**不许动** `VerticalText` 与 `TextAlign*`
- `ApplyTo` 必须写 `ManualFontSize = AutoFitText ? 0f : ManualFontSize`
- `FromCard` 必须去掉名字两端的空格
- 存盘五处：`Presets` 列表、`PresetCount`、`AppendPreset`、`TryParsePresetKey`、`ApplyPresetField`、Load 里的分支
- 名字为空的预设读取时跳过（否则菜单里会出现一条空白）
- `RefreshPresetMenu` 必须 `Dispose` 旧条目、两个列表都用预设名当标题
- `menu.Opening` 里必须调 `RefreshPresetMenu()`
- `ApplyPreset` 必须重新适应（`FitQuoteFont` + `GrowCardToText` + `BackOffToFittingSize`）

**78 处反向注入全部报出。**

## 七、这一轮修掉的验证漏洞

预设功能让**卡片与预设两条路径出现了同名键**（`ManualFontSize`、`AutoFitMaxFontSize`、`TextOutlinePercent`、`item.Text = name;`），于是几条老断言从「查整个文件」变成了**永远为真**：

| 断言 | 原来的问题 | 现在 |
|---|---|---|
| F6 `CardState` 字段 | `TextPreset` 也有 `ManualFontSize`，删掉 `CardState` 那份照样「过」 | 查 `CardState` 类体 |
| F14 保存/读取自动字号上限 | `AppendPreset` / `ApplyPresetField` 也写同名键 | 查 `AppendCard` / `ApplyCardField` 方法体 |
| F16 卡片保存描边 | 同上 | 查 `AppendCard` 方法体 |
| F17 预设条目标题 | 应用列表与删除列表各一份，改掉一处另一处还在 | `count(...) == 2` |

> **一个键出现在两个地方，所有「查整个文件」的断言就都失效了。** 这不是猜测——这一轮是反向注入一条一条把它们点出来的：注入删掉了卡片那一份，断言却一条都没报。

同时修了 6 条因为重构而失效的注入锚点（`ApplyCardField` 的参数名从 `field` 改成 `key`、`stale.Dispose()` 与 `item.Text = name;` 各出现两次、`ApplyPreset` 多了三行颜色同步）。
