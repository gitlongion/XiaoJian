# 小笺 0.9.8：行首禁则、两端对齐、卡片不透明度、文字阴影

四项一起做的原因：前三项都是「用户能看见的排版/观感缺口」，第四项（阴影）和已有的描边共用同一套机制，分开做反而要动两次绘制路径。

---

## 一、行首禁则：这是唯一一个「错误」而非「缺功能」的项

### 问题

换行器是贪心的：一行能塞几个字就塞几个，塞不下就断。对中文来说这会把标点挤到行首：

```
|人生天地之间|
|，若白驹之过|   ← 行首是逗号
|隙，忽然而已|
|。|             ← 整行只有一个句号
```

最后那一行尤其难看。这个问题在**任何**行宽下都可能出现，不是某个尺寸的特例。

### 修法

断点落在标点前面时，**把断点往前挪一个字**（CSS 的 `line-break: strict` 就是这么做的）。

- **行首禁则**：下一行不能以 `，。、；：？！）」』】〉》”’…` 开头
- **行尾禁则**：本行不能以 `（「『【《“‘` 结尾
- 连续标点（`。」`）会**一起**下移，不是只挪一个
- **有下限**：`end > index + 1`。整行都是标点时不许再往前挪，否则会断出空行——那比标点跑到行首更糟

修完之后：

```
|人生天地之|
|间，若白驹之|
|过隙，忽然而|
|已。|
```

### 为什么不做「标点悬挂」

标点悬挂（把行首标点吊在文字区外面）看起来更接近专业排版，但它会让**块比文字区还宽**。而这张卡片的最小尺寸是照块量出来的（`CardSizeLimits.MinimumFor`），块一旦能超出文字区，拖动下限就会算错。往前挪一个字不动这个约束。

## 二、两端对齐

「排版对齐」原来横轴三档（左/中/右），现在多一档**两端对齐**。

实现上它几乎是免费的：0.9.6 为了修右对齐已经改成**逐字绘制**，所以「拉伸」只剩下把 `可用宽度 - 自然宽度` 摊到字与字之间这一步。余数摊给前面几个间隙，否则右边会差一像素。

两个刻意的决定：

- **最后一行不拉伸。** 把短短的收尾行拉满整张卡片，是两端对齐最不该做的事。
- **不影响测量。** 块宽仍然是自然宽度，所以打开两端对齐不会让卡片的下限移动。这条有断言钉着（自检 215）。
- **竖排时置灰。** 竖排没有「行宽」可拉伸，留一个点了不动的条目正是这个项目一直在修的那类问题。

## 三、卡片不透明度

`Opacity = 0.97` 以前写死在 `ApplyAppearance` 里，改不了。现在是「卡片设置 → 不透明度」：100% / 97%（默认）/ 90% / 80% / 70%。

- **只重绘，不重排。** 不透明度是窗口属性，跟文字怎么排无关（自检 223 钉着「块尺寸不变」）。
- **透明背景时置灰。** 透明背景靠 `TransparencyKey` 实现，它和 `Opacity` 是同一个分层窗口的两个开关，同时改会互相打架——表现是透明区域变黑或整个窗口不显示。

## 四、文字阴影

「文字设置 → 文字阴影」：无 / 浅 / 中 / 深（0 / 3% / 6% / 10% 行高）。

和描边同一套机制，也是同一个原因：**GDI 画不了半透明文字**（`TextRenderer` 忽略颜色的 alpha 通道）。所以阴影是「同一个字形错开位置再画一次」，用**不透明的中间色**冒充柔和——颜色取文字色与背景色之间的 45%。

绘制顺序是**阴影 → 描边 → 文字**。阴影画在文字之后会盖住文字本身（这条也有注入验着）。

---

## 五、描边与阴影共用一处「留白」

原来描边自己算 `OutlinePixels * 2`，现在两项合成一个 `BlockPadding`：

```csharp
private int BlockPadding(Font font)
{
    return 2 * (OutlinePixels(font) + ShadowPixels(font));
}
```

`MeasureHorizontal`、`MeasureCell`、`TextAreaWidth`、`PaintHorizontal` 四处都读它。合成一处的原因很实际：再加第三项装饰时，只要改这个函数，四个调用点自动跟上；分散着写的话总有一处会漏，而漏的那一处表现是「开了之后文字被裁」。

阴影只往右下偏，但留白是**四边对称**的——不对称的留白会让对齐算式的中心偏掉。

## 这一轮踩到的坑

**1. 一个键出现在两个地方，断言就悄悄失效了。** 上一轮的教训在这里又出现一次：`AlignJustify` 让 `Clamp()` 里横轴的夹取从 `AlignFar` 变成 `AlignJustify`，而 `verify_portable_align.py` 里那条断言写的是旧字符串——不是「报错」，是**检查的字符串已经不存在了，所以直接报「缺少」**。这类断言只要锚点跟着改就行，但如果锚点改成了「随便什么」，它就不再验任何东西。

**2. 断言自己写错三次。** `Opacity = Math.Max(` 在 `Forms.cs` 里却写成查 `Storage.cs`；`BlockPadding` 的缩进猜错；`DrawGlyph` 的顺序检查在「文字本身没画」那条注入下会抛异常（因为没有 `ForeColor` 可比）。第三条改成先判断两个词都在再比索引——**断言要能容忍它正在验的那个缺陷**，否则缺陷被报出来的方式是脚本崩溃，而不是一条可读的问题。

**3. 自检里写 `return 30;` 污染了编号统计。** 禁则测试传了个 `delegate(char c) { return 30; }`，于是「断言编号重复 30」——统计脚本把任何 `return 数字;` 都当断言。改成 `const int cjkCell = 30;`。**这类辅助代码要避开断言编号的形态。**

**4. 插入代码执行了两遍，留下重复块。** harness 里 11b 那一段被插了两次，表现是「同一个变量名定义两次」。删除时要按标记找到第二次出现的位置再截断，不能 `replace` 第一次——那会删掉正确的那份。
