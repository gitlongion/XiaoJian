# 小笺 0.9.9：自由不透明度、背景图显示方式、圆角与边框

三项一起做的原因：它们都是「卡片长什么样」，共用同一套数据层与菜单结构；分开做要动三次 `ApplyAppearance` 和三次菜单。

---

## 一、不透明度：五个档位不是全部

原来只有 100 / 97 / 90 / 80 / 70%。现在菜单底部多一项 **「自定义…」**，可以输入 **10 到 100 之间任意整数**。

下限同时从 30% 放宽到 **10%**。30% 那个数字没有依据——它是当初随手定的，而「再淡一点」是桌面卡片很自然的需求。10% 的卡片仍然认得出是张卡；再低就找不回来了（指针不在附近时只能靠托盘图标）。

五个常用档位保留。它们是「大多数人要的」，自定义是「其余的人要的」——两者不冲突。

## 二、背景图显示方式：五种

以前固定是「铺满」（缩放到盖住卡片、裁掉多余）。现在：

| 方式 | 行为 | 什么时候用 |
|---|---|---|
| **铺满**（默认） | 缩放到盖住，裁掉多余 | 照片做背景，不介意裁 |
| **适应** | 缩放到完整可见，留边 | 图里有完整构图，不能被裁 |
| **拉伸** | 填满，不保持比例 | 纯色/纹理图，不怕变形 |
| **平铺** | 原始大小重复 | 小图案（纸纹、格子） |
| **居中** | 原始大小居中，超出裁掉 | 小图标，要像素级清晰 |

几何上只有两个函数：`CoverRectangle` 取两轴比例的**最大值**（盖住），`FitRectangle` 取**最小值**（装下）。写反了就会变成「适应」反而裁图、「铺满」反而留白边——这条有断言和注入双向验着。

没有背景图时，这一项**置灰**：显示方式在没有图的时候没有意义。

## 三、圆角：上限 40 不是随手定的

原来半径是写死的 18。现在可选 直角 / 8 / 18 / 28 / 40，另有「自定义…」输入 0–40。

**为什么上限是 40**：文字区距卡片边缘 12 像素（`TextPadLeft`），而半径为 R 的圆角要「不切到文字区左上角那个点」，条件是

```
R * (√2 - 1) <= 12 * √2     →     R <= 12 * √2 / (√2 - 1) ≈ 40.97
```

所以 40 是仍然安全的**最大整数**。41 开始，文字的第一个字就会被自己的圆角切掉一点。

这条现在有两个断言盯着：自检 230/231（按几何量比内边距）和 `verify_size.py` Z15（把上限改成 200 就报错）。**以前这里比的是 `R/2`**——那是个既松又和几何无关的替身：上限调到 40 时它只要求内边距 20，而实际切进来的是 11.7。

半径还有**第二个上限**，来自卡片自己：半径大于短边的一半时，`RoundedRectangle` 的四个弧会重叠，画出来是个蝴蝶结。所以 `CornerRadiusFor(requested, width, height)` 同时按两者收窄——一张 60×40 的小卡片上选「很圆」，实际画出来是 20。

## 四、边框：粗细 + 颜色

粗细 0（无）/ 1（细，默认）/ 2（中）/ 3（粗），另有边框颜色。

两个细节：

- **粗细为 0 时直接不画**。留一条 1 像素的线比「没有边框」更糟——用户会以为设置没生效。
- **粗边框要往里让半个笔宽**。`Pen` 以路径为中心向两侧各画一半，2 像素的边框如果还画在边界上，外面那一半会被窗口边缘裁掉。1 像素保持原位不动——挪它会让每一张现有卡片的轮廓都移动一像素。

透明背景的卡片**不画边框**（没有可依附的底），所以那一项也置灰。

## 五、顺带修掉的一个老观感问题

窗口的圆角区域和画出来的边框曲线**原本不是同一个半径**：

```csharp
CreateRoundRectRgn(0, 0, W + 1, H + 1, 19, 19)   // 19 是椭圆直径 → 半径 9.5
RoundedRectangle(rect, CardSizeLimits.CornerRadius)  // 半径 18
```

`CreateRoundRectRgn` 收的是**椭圆尺寸**，不是半径。所以窗口被裁成半径 9.5 的形状，而边框画在半径 18 的弧上——每个角上露出一小片背景色（白底白卡看不见，配了背景图就能看见）。

现在两者都走 `CornerRadiusFor`，且区域用 `radius * 2`。半径为 0 时改调 `CreateRectRgn`——不去赌「椭圆尺寸传 0 会退化成矩形」这种没人测过的行为。

## 这一轮的四个坑

**1. `OnPaint` 在文件里有两个。** `safe_body` 要求签名唯一，于是报「出现 2 次」。改用 `body_by_marker`（按方法体里的 `_locatingCard` 挑卡片那个）——**同名重载要靠方法体特征挑，不能靠签名**。

**2. 注入串的换行多写了一层反斜杠。** 在 heredoc 里写 `\\\\n` 落到文件是 `\\n`（两个反斜杠），而锚点需要的是一个反斜杠 + n。四条注入同时报「注入点没找到」。**写完注入先跑一遍，报「找不到」时先怀疑转义，别先怀疑源码。**

**3. 断言漏了一条，注入才把它逼出来。** 「显示方式不夹在五档之内」注入删掉夹取，一条都没报——因为 F19 里我检查了圆角和边框的夹取，**唯独漏了显示方式**。补上之后才 107/107。

**4. 又插了两次。** harness 的 11d 段落出现两次，表现是「同一个变量名定义两次」。删除要按标记找**第二次**出现的位置再截断。

**还有一条不是坑但值得记**：`MaxCornerRadius` 从 `CardSizeLimits` 挪到了 `CardState`（它是每张卡片的数据），`CardSizeLimits` 只留几何函数 `CornerRadiusFor`。`verify_size.py` 的 Z15 因此要改成从 `storage` 读常量——**常量搬家会打断断言，而表现是「找不到」，不是「值不对」**。
