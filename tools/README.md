# 验证脚本

这个程序是 Windows 的 WinForms。开发机是 macOS，跑不了 exe —— 所以「功能是好的」这句话
不能靠点一遍，只能靠这里的脚本。它们分四类：

| 脚本 | 验什么 |
| --- | --- |
| `verify_size.py` | 卡片尺寸的下限：只约束「横跨文字流向」的那根轴 |
| `verify_font_library.py` | 字号调整、每卡内容库、菜单结构、拖动吸附、圆角路径、原子写 |
| `verify_portable_align.py` | 便携式数据目录、排版对齐、改名与升级路径 |
| `verify_shutdown_path.py` | 退出路径（关窗、托盘、开机启动清理）不许留下半截状态 |
| `verify_font_sim.py` | 字号链路的**带状态**仿真：按真实常量跑一遍「文字变大 → 卡片长高」 |
| `verify_shrink_sim.py` | 拖动缩放的收敛仿真，带 `--old` 用被换掉的公式跑同一套断言 |
| `verify_icon.py` | `card.ico` 的七档结构、逐档像素、平均亮度 |
| `verify_exe.py` | PE 结构、程序集元数据、内嵌图标与 `card.ico` 逐字节对照 |
| `harness/` | 把不依赖 WinForms 的纯逻辑原样抽出来，在 .NET 8 上真跑（170 项） |

## 怎么跑

```sh
sh tools/verify_all.sh
```

需要 Python 3（`verify_*.py` 用到 Pillow 读图标像素）和一个能还原 net40 参考程序集的 dotnet。
路径都可以用环境变量覆盖：`PYTHON`、`DOTNET`、`PREV`。

## 关于「反向注入」

每个脚本都有 `--reverse`：它会把源码里某一行故意改坏，再跑同一套断言，**必须报出问题**。
报不出来就说明那条断言是空的。这是断言有没有用的唯一证据 —— 报告上全是绿的，可能只是
因为断言早就变成了永远为真。

`verify_all.sh` 第 11 步是同一个思路的对照版：把某个旧版本的源码指进来（`PREV=<目录>`），
新断言应该在它身上报出一堆问题。没设 `PREV` 时这一步会**明说跳过**，不会打印「0 条」——
「0 条问题」和「什么都没验」在输出上长得一模一样，这个坑踩过。

## 这些脚本认的是源码文本

断言里直接查代码片段（`if "state.Opacity.Enabled = ..." not in forms`），所以**改名、搬家、
调整缩进都会让它们失效**。改完源码要跑一遍 `--reverse` 确认锚点还在；报「找不到 XX」时，
先怀疑锚点，别先怀疑代码。
